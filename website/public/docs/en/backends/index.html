Backends and licenses

Understand common engines, availability, explicit selection and licenses.

On this page
Common engines and tasksDiscovery, selection and executionAfter installation or updatesConfigure commercial licensesLocate environment issuesNative references

A backend performs mathematical computation. Settings discover native IDs, availability and reasons in the solver environment; results retain the actual engine.

Common engines and tasks#

EngineModel directionExample platform entry
HiGHS, CBC, GLPKSupported LP/MIPCompatible Pyomo/PuLP interfaces
SCIPLinear, integer and native nonlinear constraintsPySCIPOpt, OR-Tools and others
CP-SATFinite integers, Booleans and schedulingOR-Tools, CPMpy
Gurobi, COPTNative mathematical programminggurobipy, coptpy and compatible interfaces
OSQPContinuous convex quadratic objectives, linear constraintsCVXPY
Clarabel, SCSContinuous conesCVXPY
MOSEKSupported native mathematicsCVXPY and compatible interfaces
IpoptSmooth continuous NLPCasADi and others
BonminCompatible mixed-integer nonlinear modelsCasADi plugin
SAT, SMT, MiniZinc familiesFinite domains and logicCPMpy native backends

Choose exact IDs from settings. The same engine can have different identifiers across libraries, including separate command-line and Python adapters.

Discovery, selection and execution#

AUTO follows native library/model logic; CVXPY uses compatible installed paths. Explicit selection fixes the engine. Errors identify interface, dependency or license issues.

After installation or updates#

Compose builds backend dependencies into the Worker. Python setups use uv run llm4om build-worker. For custom dependencies, update the Worker environment, rebuild and restart.

The service caches its backend catalog. Restart after dependency or license changes to discover again. Run a complete small model from the library guide to check the selected path.

Configure commercial licenses#

EngineEnvironment variableExample file
GurobiGRB_LICENSE_FILE/opt/gurobi/gurobi.lic
MOSEKMOSEKLM_LICENSE_FILE/opt/mosek/mosek.lic
COPTCOPT_LICENSE_DIRDirectory with license.dat and license.key

Prepare an offline, container-compatible license on the host. Mount identical absolute paths into app. Example compose.override.yaml:

services:
  app:
    volumes:
      - /opt/gurobi/gurobi.lic:/opt/gurobi/gurobi.lic:ro
      - /opt/mosek/mosek.lic:/opt/mosek/mosek.lic:ro
      - /opt/copt/license.dat:/opt/copt/license.dat:ro
      - /opt/copt/license.key:/opt/copt/license.key:ro

Set the corresponding .env variables and run docker compose up -d app. Workers mount the specified files read-only. Keep entries for the engines you use.

Locate environment issues#

ErrorInspect
Executable missingWorker installation and PATH
Plugin cannot loadNative libraries, drivers and dependencies
License path/host mismatchPaths, container compatibility and license contents
Unsupported model typeDomains, expressions and engine capabilities
Model-size restrictionLicense and intended model size

Retain complete errors with engine information for inspection. See troubleshooting.

Native references#

See Gurobi documentation, MOSEK client setup and COPT installation/licensing. Use solver selection for interfaces and mathematics.
