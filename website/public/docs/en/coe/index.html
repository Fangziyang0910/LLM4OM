Modeling methods/Chain-of-Experts

Chain-of-Experts

A conductor selects experts in sequence before a reducer produces the model.

On this page

Chain-of-Experts (CoE) asks a conductor to select experts in sequence. Later experts read earlier comments; a reducer produces the final model and code. Each comment enters the pool available to later roles.

How comments affect the next step#

The conductor chooses among seven expert roles. Each expert sees the problem and the current comment pool, so later comments can extend or correct earlier ones. The default selects three experts per trial before reduction.

Each expert uses its role prompt and current comment pool with the run's selected LLM preset.

Workflow and collaboration example#

FOLLOW THE EXAMPLE
1. Interpret

This example follows useful comments into the pool, beginning with business terminology.

Illustrative comment: unit profit differs from revenue; processing hours per unit differ from total hours.
2. Add modeling detail

A later expert reads existing comments and adds domains, indices or resource constraints instead of repeating them.

Illustrative comment: use nonnegative integers for whole products.
Cutting: 2A+B≤8; finishing: A+2B≤8.
3. Reduce

The reducer must turn comments into one internally consistent model. Conflicting comments still require an explicit final choice.

A cannot be both continuous and integer in the final interpretation.
Check which comments survive in the code.
4. Read the default path

Reflection is disabled by default. Do not interpret every run as repeated execution-failure attribution. The final model is still solved by the platform.

Default: three experts → reduction → platform solve
Reflection is a deployment-preset branch.

Worked example: illustrative inputs and intermediate artifacts.

What reflection actually means#

When enabled, reflection is triggered by execution failure. Experts are questioned backwards from the latest speaker; the first accepting responsibility refines its comment. Each new trial clears the comment pool, so separate trials do not share an accumulating pool.

enable_reflection=false is the default. max_trials=3 matters when reflection is enabled. Execution checks use whether the code obtains a solver status.

Reading and comparing runs#

Look for new information: a missing rule, resolved ambiguity, domain issue or objective correction. The final model shows how comments became expressions used in computation.

Use CoE for LP/MILP collaboration workflows and method comparisons. For explicit per-constraint checks see SAC-Opt; for problem-type retrieval see OptiTree.

Source and platform adaptation#

The pinned Chain-of-Experts implementation supplies the conductor, seven expert roles and reducer prompts. Native-library contracts replace original examples. Execution uses real attachments in the sandbox instead of LLM-invented test inputs.

Current parameters#

Parameters come from the deployed method preset. They are saved with each run and cannot be changed per run in the UI, CLI or Python API.
