Deployment & reference/Troubleshooting

Troubleshooting

Resolve connection, LLM, solver and result issues from the actual error.

Start with the failed stage and complete error. The following checks cover connections, model requests, execution, validation and recovery.

Identify the failing layer#

LocationInspect firstVerification
Page does not openService terminal or Compose logsThe listening address opens in a browser
Failure before generated contentAI model settings and failed callThe selected preset completes a small problem
Execution fails after generationExecuted code and complete error in Solving StepsWorker and selected backend are available
Solve succeeds but the plan is wrongThat version's statement, formulation and domainsConstraints match the business requirements
Language or formulas look wrongLanguage and display guidance belowSeparate translations, source models and raw logs

Keep the run link before retrying. Retain the original failure evidence; a successful execution does not establish that the model matches the problem.

Pages and service connections#

SymptomCheck/action
Local page unavailableInspect docker compose ps and docker compose logs -f app
Other devices cannot connectCheck server IP, mapping, firewall and security group
HTTPS certificate issueCheck DNS, ports 80/443 and docker compose logs -f https
Interrupted live progressRefresh the run link; inspect proxy streaming and server logs

Python startup prints the listening address and workspace. Compose uses LLM4OM_PORT.

Presets and model requests#

ErrorAction
401Check key and provider
404Check endpoint, protocol and model ID
Structured-output/tool-choice errorInspect service tool support, method and advanced parameters
TriVAL model request failsCheck the preset endpoint, model ID and tool-calling support; TriVAL uses the preset's thinking settings
Quota messageCheck daily usage and select an available preset or continue next day

Failed saves retain entered values. Follow preset configuration, then confirm with a small example.

Execution environment and code#

For a missing Worker, run docker compose up -d --build, or uv run llm4om build-worker in Python setups.

For Docker connection errors, inspect the service, socket permissions and DOCKER_SOCKET. For backend/license failures, read complete feedback and follow backend setup.

On Windows, Docker Desktop's Linux engine must be running. Start with docker info. If virtualization is unavailable, check WSL 2, Windows virtualization components and firmware settings, following Docker Desktop's diagnostics. Changes to Windows features or boot settings can require administrator access and a restart; they are not routine solving steps.

The default Docker Worker executes generated code and calls the solver; model requests originate on the server. Replacing an API key does not repair the Docker engine, and rebuilding the Worker does not repair authentication.

Execution errors identify exceptions and stages. Locate file names, fields, indices, return objects or APIs, then rerun the appropriate repair workflow from the problem.

Method validation and solver results#

TriVAL retains semantic, formulation and code validation; SAC-Opt retains per-constraint comparisons; Feedback Repair retains accept/repair reasons. Failure messages identify stages, with artifacts and executions in the process view.

Open the relevant stage and compare feedback with its model/code version. Method articles provide stopping conditions, return paths and parameters for following the run.

Infeasibility and native statuses#

Use conflict analysis when IIS/MUS evidence is available, then revise the relevant rules. For nonlinear paths, inspect starts, bounds and native feedback before computing further scenarios.

Run information records time, calls and quotas. See configuration for limits and solvers for mathematical selection.

Language, formulas and reading translations#

SymptomAction
A foreign-language statement remains visibleSource statements are retained; use the reading translation in Problem and data and switch to the original when needed
Historical model explanations use another languageWait for the reading translation; a Translate to Chinese action is available for some mixed-language content
English or JSON appears during solvingView raw model output shows the actual response, which can contain code, English and tool protocols; it is separate from the localized model reading view
Variables show var_type, domain or shapeFixed model labels are localized in the reading view. Hard-refresh to load current assets; code and raw logs retain protocol names
Expressions such as x_A appear as plain textCheck for $...$, $$...$$ or math delimiters in the source; translation does not automatically convert bare text into formulas
An example translation fails or is emptyKeep the source; check the default available preset, connection and quota, then retry. Existing plans need no new solve

New runs request explanations in the interface language. This does not guarantee the same language in provider reasoning. A statement and interface already in the same language usually need no reading translation.

Example and reading translations translate natural language, including table headings and descriptive cells, while requesting unchanged numbers, formulas, variable names, code and table structure. Generation uses the server's default available preset and counts toward its quota. The same source, target language and translation rules reuse the local cache. Check important units, negations and constraint directions against the source; translations can be wrong.

Copies, downloads, literal version differences and subsequent modeling use the original content. Explicitly choosing Use translation in the example library makes the translation the new run's statement; inspect it before solving.

Recovery and issue records#

Refresh reconnects conversations to active runs; open saved plans from cards or history. Retry original messages after stopping. Batch retries reuse saved scenarios and continue remaining work.

Capture the run link, method, library, backend, public preset configuration, failed stage, complete error, relevant statement, and expected versus actual behavior. Remove credentials, licenses and sensitive business data before sharing; do not upload .env or the entire private workspace. See maintenance for logs and backups.
