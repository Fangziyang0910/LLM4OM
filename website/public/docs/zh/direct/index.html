建模方法/Direct

Direct

一次生成数学模型与求解代码，再交给求解器计算。

本页内容
它解决哪一步执行流程与逐步案例怎样判断结果是否可信调用、停止与适用场景平台实现与比较当前参数

Direct 把问题说明、数据说明和所选建模库的要求一次性交给大模型，要求同时写出数学模型和完整代码。平台随后执行代码并调用真实求解器。它的流程短，适合作为第一次尝试，也适合给其他方法提供比较基准。

它解决哪一步#

Direct 先把业务规则写成变量、目标和约束，再把数学表达写成建模代码。一次回复完成这两次转换，随后进入真实求解。

以生产计划为例：A、B 每件收益为 3 和 2；切割分别用 2 和 1 小时，装配分别用 1 和 2 小时，两种资源各有 8 小时；产品必须按整件生产。

max⁡  3A+2Bs.t.2A+B≤8,  A+2B≤8,  A,B∈Z≥0.\max\;3A+2B\quad\text{s.t.}\quad2A+B\le8,\;A+2B\le8,\;A,B\in\mathbb Z_{\ge0}.max3A+2Bs.t.2A+B≤8,A+2B≤8,A,B∈Z≥0​.

关键是整数域、资源系数、工时单位和最大化方向是否全部正确。

执行流程与逐步案例#

跟着案例看流程
1. 读题

先确定什么是决策、什么是输入。收益和工时是给定参数，A、B 的产量才是待求变量。

输入：利润 (3, 2)；切割 (2, 1)；装配 (1, 2)；容量 (8, 8)
数量必须为非负整数。
2. 生成

同一回复提供数学模型与 build_model(data)。附件预览即使截断，代码也应读取完整附件。

变量：A, B ∈ 非负整数
目标：max 3A + 2B
约束：2A + B ≤ 8；A + 2B ≤ 8
3. 计算

代码返回原生模型，由平台调用兼容后端计算。数值不由大模型猜测。

整数最优：A = 3，B = 2，收益 13
切割：8 / 8；装配：7 / 8
4. 核对

结果页将模型、代码和实际方案保存在一起，可以继续导出、讨论和调整条件。

结果：A = 3，B = 2，收益 13
下一步：导出 CSV，或将切割容量调整为 10 小时后重算。

教学案例：用示例输入和中间产物逐步说明流程。

怎样判断结果是否可信#

先核对问题到数学模型，再核对数学模型到代码，最后核对数值。上例可手算 2×3+2=8、3+2×2=7、3×3+2×2=13。结果页的公式、代码和数值可在同一份运行记录中查看。

特别检查“至少”是否写成 ≥、“最多”是否写成 ≤，以及要求是逐天、逐产品还是按总量成立。把每天至少三人误写成全周至少三人，代码仍可能成功运行。

动手试：资源、整数与无解可交互
A = 3, B = 2 · 13

最大化 3A + 2B；2A + B ≤ 8，A + 2B ≤ 8。整数最优收益为 13。

固定教学案例，数值在浏览器中即时计算。

调用、停止与适用场景#

Direct 的建模阶段只有一次大模型调用，不在内部修复格式、执行或语义错误。缺少模型或代码时直接报告失败；完整代码执行失败时保存反馈。方案解读等后续功能可能另有调用。

题目短、规则清楚、希望快速查看第一个模型时，可以从 Direct 开始。若模型能运行但容易漏掉业务约束，考虑 Feedback Repair；若想观察分层验证，查看 TriVAL；若主要困难是大附件的数据绑定，查看 BIND。

平台实现与比较#

Direct 由本项目维护，与 Feedback Repair 共用生成提示。它不限制为线性问题，但具体表达必须由所选建模库和后端支持。比较方法时，固定题目、附件、模型预设和求解器，才能更清楚地观察编排流程造成的差异。

当前参数#

参数来自部署时的方法预设，随每次运行记录保存。页面、命令行和 Python 接口均不提供单次运行的参数修改。

Direct 没有方法专属的预设参数。
