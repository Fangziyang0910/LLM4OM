选择建模库与求解器

了解九个建模库，以及后端能力、AUTO 和实际可用状态。

本页内容
九个建模库怎样选择组合AUTO 与显式后端代码如何交给平台

建模库负责表达数学模型，求解后端负责计算。先判断问题的变量与约束，再选择能表达并求解它们的组合。

九个建模库#

建模库常见用途默认或原生引擎
Pyomo代数形式的线性、整数与其他优化模型代数模型通常用 HiGHS；Kernel 默认 CBC
gurobipyGurobi 原生模型与矩阵建模Gurobi
OR-ToolsLP/MIP、CP-SAT、路径、网络流等按原生接口选择
CPMpy有限域整数、布尔和全局约束OR-Tools CP-SAT
PuLP线性与混合整数规划CBC
CVXPY凸优化、锥模型、DGP/DQCP按原生兼容路径选择
PySCIPOptSCIP 原生线性、整数、非线性约束SCIP
CasADi光滑非线性与插件支持的其他模型Opti NLP 默认 Ipopt
coptpyCOPT 原生线性、整数、凸二次与锥模型COPT

怎样选择组合#

生产、运输等 LP/MILP 可以从 Pyomo 或 PuLP 的开放后端开始；离散排班和逻辑约束可考虑 CPMpy 或 OR-Tools CP-SAT；凸二次或锥模型可查看 CVXPY；光滑非线性可查看 CasADi。具体选择还取决于方法范围与安装环境。

选择 CPMpy 不会使连续决策变成合法整数决策。选择一个 LP 后端也不会放松整数域；平台会报告不兼容，而不是静默求解连续松弛。

AUTO 与显式后端#

AUTO 使用该库和模型的原生选择逻辑。运行设置列出当前沙箱中的后端及可用原因。显式选择后端后，失败不会自动替换成其他引擎；最终结果记录实际使用的求解器。

库内 API 由生成代码表达，平台识别原生模型。OR-Tools 的 MPSolver、MathOpt、CP-SAT 和 Routing 等不是四个额外的建模库选项。

代码如何交给平台#

通常，代码定义 build_model(data)，构建并返回原生模型。平台负责求解，代码不直接调用 solve 或打印方案。Routing、网络流和部分 CasADi 接口还需返回管理器、源汇或数值参数，详见各库文章与原生接口说明。

后端列表中的名称、成功加载插件和具备可用商业许可是不同条件。安装与许可证见求解后端。

↗Pyomo用代数方式表达模型，并连接兼容的原生求解后端。↗gurobipy / Gurobi使用 Gurobi 的原生 Python 模型、矩阵接口与冲突诊断。↗OR-Tools覆盖线性、整数、约束、路径与网络流等原生接口。↗CPMpy用整数、布尔与全局约束表达离散决策。↗PuLP表达线性与混合整数模型，连接 CBC 等原生后端。↗CVXPY表达凸优化模型，选择支持相应锥与变量域的后端。↗PySCIPOpt / SCIP使用原生 SCIP 表达线性、整数及非线性约束。↗CasADi表达光滑非线性模型，理解插件与局部求解状态。↗coptpy / COPT使用 COPT 原生接口，核对模型类型与许可条件。↗求解后端与许可证认识常用引擎、安装状态、显式选择与许可证配置。
