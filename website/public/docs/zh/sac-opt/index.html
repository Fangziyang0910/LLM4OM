建模方法/SAC-Opt

SAC-Opt

提取语义锚点，回译约束代码，只修正未通过的组件。

本页内容
执行流程怎样使用查看哪些产物独立实现与来源当前参数

SAC-Opt 提取参数、变量、目标和约束四类语义锚点，再把约束代码回译成文字，与原始约束比较。已经通过的约束冻结，只修正未通过的组件。

执行流程#

语义锚点 → 分项代码 → 约束回译 → 比较
                        ↑         ↓ 未通过
                        └─ 选择性修正
             → 组装 → 求解 → 执行错误调试

回译阶段不读取原始约束，比较器再判断回译与原约束是否一致。这样可以定位具体组件，而不是每次重写全部代码。

怎样使用#

选择 SAC-Opt 处理 LP/MILP 问题。它适合逐项检查约束表达的工作流。准备清楚的业务规则，并在过程里查看锚点与每条约束的对应关系。

平台通过共享组件支持九个库，完整附件在 build_model(data) 中读取。变量域与上下界仍必须忠实于题面，不能为兼容库而放松。

查看哪些产物#

检查锚点、组件、回译、逐项比较及选择性修正。当前回译循环检查约束，不单独验证目标。语义轮数用尽仍有未通过组件时，平台会保留实际模型与结果，同时明确说明语义检查失败。

独立实现与来源#

本平台根据 SAC-Opt 论文和固定参考提交独立实现。上游该提交未声明许可证，因此没有复制其代码和提示。平台批量处理组件并采用自己的结构化输出要求，保留语义锚点与选择性修正机制。

当前参数#

参数来自部署时的方法预设，随每次运行记录保存。页面、命令行和 Python 接口均不提供单次运行的参数修改。

参数取值
temperature0
max_parse_attempts5
max_semantic_rounds5
max_executions3
