配置与启动建模

选择建模方法、建模库、求解后端和预设模型。

本页内容
选择四项配置检查问题再启动跟踪过程遇到配置不兼容

手动工作台适合先检查完整问题与配置，再明确启动一次计算。优化对话也能指定这些配置，详见Chat Agent。

选择四项配置#

点击问题上方“查看运行设置”或“调整配置”。

配置选择依据
建模方法决定生成、验证和修复流程，见方法指南
建模库要能表达变量、目标和约束，见库与求解器
求解后端选择已安装且与模型兼容的原生引擎；默认 AUTO
预设模型选择实际调用的大模型服务

方法参数在部署预设中固定，不是每次运行可调的表单项。运行记录会保存本次实际参数，方便后来核对。

检查问题再启动#

确认决策、目标方向、约束、单位、整数或连续变量要求，以及附件字段。可以切换 Markdown 编辑与预览。问题中的公式建议用 \(...\)、\[...\] 或 $$...$$，普通价格中的单个 $ 保留为文本。

点击“完成”收起配置，再点击“开始建模”，或使用 Ctrl+Enter / Cmd+Enter。附件尚在读取时，等待读取完成。

跟踪过程#

运行在服务器上执行，页面展示实际步骤。关闭浏览器不会中断后台运行；重新打开可以读取已有过程和当前进度。主动停止后，保存的步骤仍可查看，但不表示方法能从中断节点继续。

遇到配置不兼容#

建模库可表达的接口不等于每个后端都支持该模型。例如整数变量需要支持整数域的后端。显式选择的后端失败时不会静默替换。查看完整错误，再调整配置或模型表达，避免误用连续松弛结果。
