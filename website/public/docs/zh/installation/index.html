开始使用/安装与启动

安装与启动

使用 Docker Compose 或本地 Python 环境启动平台。

本页内容
准备环境使用当前 Codex 或 Claude Code 模型使用 Docker Compose 启动从页面确认安装使用 Python 环境启动常用维护命令官网与平台地址

可以用 Skill 直接使用当前 Codex、Claude Code 模型，也可以使用 Web 工作台。已有团队平台地址时，直接打开浏览器即可。要运行自己的服务，可以用 Docker Compose 安装工作台、服务和求解环境。

准备环境#

方式需要的环境适合用途
宿主 Skilluv、Git、Node.js 22.20+、Docker、Codex 或 Claude Code使用宿主当前模型，无需平台 API Key 或 Web 部署
Docker ComposeDocker、Compose v2.24或更新版本、模型服务配置个人或团队运行
Python启动Python 3.11–3.13、uv、Docker、模型服务配置开发或已有Python环境

运行数据保存在工作区或Compose数据卷中。安装前选择一台可持续保存数据并访问模型服务的机器。

使用当前 Codex 或 Claude Code 模型#

CLI、求解环境和 Skill 使用相同发布版本：

uv tool install --python 3.12 git+https://github.com/Fangziyang0910/LLM4OM@v0.43.0
llm4om build-worker
npx skills add https://github.com/Fangziyang0910/LLM4OM/tree/v0.43.0/skills/llm4om --skill llm4om -g -a codex -a claude-code

运行 llm4om --version 确认显示 LLM4OM 0.43.0，运行 llm4om backends 检查求解镜像。安装后新开宿主会话，在 Codex 中输入 $llm4om，或在 Claude Code 中输入 /llm4om。发送快速开始的生产题，可指定 Feedback Repair 和 Pyomo；该例应得到 A=3、B=2、利润=13。

宿主当前模型负责理解、建模、写代码和解释实际结果。CLI 保留方法阶段，在本机执行工具与求解。不需要配置 .env、平台预设模型或 Web 服务。npx 安装技能文件，CLI 与 Docker 仍需分别准备。

只用一个宿主时，保留对应的 -a 参数。完整示例、升级、卸载与安装问题见双语宿主建模指南。已验证 Linux；macOS、Windows 尚未完成整套安装验证。

使用 Docker Compose 启动#

git clone https://github.com/Fangziyang0910/LLM4OM.git
cd LLM4OM
cp .env.example .env
chmod 600 .env

在编辑器中打开 .env，填写服务商、接口地址、模型ID与密钥。示例字段见模型预设。然后运行：

docker compose up -d --build
docker compose ps

构建完成后打开 http://localhost:8767。首次运行会下载依赖并构建 Worker；启动日志可通过 docker compose logs -f app 查看。

从页面确认安装#

打开工作台，检查默认模型预设和运行设置中的后端选项。按快速开始输入生产题，完成一次生成与求解；页面应保存产量、模型、代码和运行步骤。

之后可添加附件、尝试优化对话，或在另一台设备使用服务器地址访问。共享访问和HTTPS见团队部署。

使用 Python 环境启动#

在已经克隆的仓库中执行：

uv sync --all-extras
uv run llm4om build-worker
uv run llm4om serve --workspace runs/web --port 8767

该方式使用仓库提供的工作台构建文件，Python服务通过Docker沙箱完成求解。工作区 runs/web 保存历史与预设；使用其他位置时通过 --workspace 指定。

常用维护命令#

操作命令
查看运行状态docker compose ps
查看服务日志docker compose logs -f app
应用更新git pull 后执行 docker compose up -d --build
应用环境变量变化docker compose up -d app
停止服务并保留数据卷docker compose down

模型连接问题见预设配置，后端问题见求解环境，历史数据备份见配置与备份。

官网与平台地址#

GitHub Pages 发布官网和Docs。完整平台使用上述机器运行Python服务与求解环境；团队成员使用部署后的服务地址计算自己的问题。
