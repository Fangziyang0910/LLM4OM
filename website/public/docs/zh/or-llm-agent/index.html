建模方法/OR-LLM-Agent

OR-LLM-Agent

先建立数学模型，再写代码，结合执行反馈修复与复查。

本页内容
执行流程怎样使用核对最终代码与结果来源与平台适配当前参数

OR-LLM-Agent 先写数学模型，再生成代码，并结合执行错误做修复。主轮之后还有不可行检查或模型复查。

执行流程#

数学模型 → 求解代码 → 执行 → 错误修复
         → 根据结果进行不可行检查或复查

流程保留不同轮次的尝试额度。主轮、不可行检查和复查分别使用预设中的 attempts，而不是统一的无限重试。

怎样使用#

选择 OR-LLM-Agent 处理 LP/MILP 问题。它适合希望先看到独立数学表达，再观察代码执行反馈与复查的工作流。方法中的“Agent”指这套建模流程；网站中的 Chat Agent则是可以调用不同方法的对话入口。

核对最终代码与结果#

修复对话使用副本，只把最后一次代码带回主对话。上游在最后一次修复后可能不再执行；平台将未执行代码作为中间产物保存，最终数值关联最后一次实际执行的代码。阅读结果时，应同时核对代码版本与实际执行步骤。

来源与平台适配#

核心流程来自 OR-LLM-Agent 固定提交。平台保留提示与恢复路线，将原 Gurobi 代码请求替换为所选库的代码契约，并在沙箱中执行。

当前参数#

参数来自部署时的方法预设，随每次运行记录保存。页面、命令行和 Python 接口均不提供单次运行的参数修改。

参数取值
temperature0.2
attempts{"main":3,"infeasible":1,"recheck":2}
