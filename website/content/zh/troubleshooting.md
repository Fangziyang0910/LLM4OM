从运行页的失败阶段和完整错误开始定位。下面按连接、模型请求、求解环境、验证和恢复列出实际检查入口。

## 先确定问题发生在哪里

| 发生位置 | 先看哪里 | 可确认的结果 |
|---|---|---|
| 页面无法打开 | 服务终端或 Compose 日志 | 服务监听地址可从浏览器访问 |
| 模型还没生成内容就失败 | AI 模型设置、失败调用 | 当前所选预设能完成一个小问题 |
| 模型已生成，执行阶段失败 | 求解步骤中的执行代码与完整错误 | Worker 和所选后端可用 |
| 求解成功但安排不合理 | 该版题面、数学模型、变量域 | 模型约束与业务要求一致 |
| 语言或公式显示不正确 | 下方“语言、公式与阅读译文” | 区分显示译文、模型原文和原始日志 |

保留当前运行链接再重试。不要删除记录来掩盖最初的错误，也不要把“运行成功”当作题意已经核对通过。

## 页面与服务连接

| 现象 | 检查与操作 |
|---|---|
| 本机打不开页面 | `docker compose ps`查看状态；`docker compose logs -f app`查看启动信息 |
| 其他设备打不开 | 检查服务器IP、端口映射、防火墙与安全组 |
| HTTPS证书问题 | 核对域名解析、80/443端口，查看 `docker compose logs -f https` |
| 流式进度中断 | 刷新运行链接重新连接；检查代理的实时流配置与服务日志 |

Python启动时查看终端打印的监听地址和工作区；Compose端口由 `LLM4OM_PORT` 决定。

## 模型预设与请求

| 错误 | 处理位置 |
|---|---|
| 401 | 核对密钥与服务商 |
| 404 | 核对接口地址、协议和模型ID |
| 结构化输出或工具选择错误 | 查看服务的工具支持、所选方法及高级参数 |
| TriVAL 的模型调用失败 | 检查预设地址、模型 ID 和工具调用支持；TriVAL 沿用预设的思考配置 |
| 额度提示 | 在预设窗口查看当天用量，选择可用预设或等待下一日 |

预设保存失败保留已输入内容。按[模型配置](../model-presets/)重新添加正确配置，再用小案例确认调用。

## 求解环境与代码执行

找不到Worker镜像：Compose运行 `docker compose up -d --build`；Python方式运行 `uv run llm4om build-worker`。

Docker连接错误：检查Docker服务、socket权限与 `DOCKER_SOCKET` 路径。后端加载或许可错误：打开完整反馈，按[后端指南](../backends/)核对原生依赖和挂载文件。

Windows 自建服务还需要 Docker Desktop 的 Linux 引擎正常运行。先执行 `docker info`；如果提示虚拟化不可用，检查 WSL 2、Windows 虚拟化组件和固件虚拟化设置，按 Docker Desktop 的提示处理。启动项修改或 Windows 功能调整可能需要管理员权限与重启，不要把修改系统启动配置当作常规求解步骤。

默认 Docker Worker 执行生成代码并调用求解器；模型预设请求由服务端发起。修改 API 密钥不会修复 Docker 引擎错误，重建 Worker 也不会修复模型鉴权失败。

代码错误显示具体异常与执行步骤。可定位文件名、数据字段、索引、模型返回对象或库API，再从原题运行所需修复流程。

## 方法验证与求解结果

TriVAL保存语义、公式和代码验证状态；SAC-Opt保存逐约束语义比较；Feedback Repair保存接受或修复理由。运行页的失败信息会指向具体阶段，过程页保留产物和执行结果。

先打开该阶段，阅读反馈，再对照对应版本的模型和代码。各方法文章提供停止条件、返回路径与参数，可以直接定位运行走到哪一步。

## 不可行与原生状态

有IIS或MUS证据时，使用[冲突分析](../conflicts/)找到业务规则并进入调整。非线性路径可查看初值、边界和原生反馈，再运行其他场景。

时限、调用次数和每日额度在运行信息中有对应记录。调整部署额度见[配置](../configuration/)，选择模型类型见[求解器](../solvers/)。

## 语言、公式与阅读译文

| 现象 | 处理方式 |
|---|---|
| 中文界面仍看到英文原题 | 原题按输入保留；“问题与数据”提供阅读译文，可切换查看原文 |
| 历史数学模型的说明是英文 | 等待阅读译文；若自动判断没有触发，可使用页面提供的“翻译为中文”入口 |
| 求解时出现英文或 JSON 字段 | “查看模型原始输出”展示实际返回内容，可能包含代码、英文和工具协议；它不等于本地化的模型阅读视图 |
| 变量处出现 `var_type`、`domain`、`shape` | 固定模型字段在阅读视图中显示为本地化标签；先强制刷新以加载最新页面资源。代码和原始日志仍保留字段名 |
| 公式显示为 `x_A` 等普通文字 | 检查原文是否使用 `$...$`、`$$...$$` 或数学分隔符；翻译不会自动把裸文本改写成公式 |
| 题库译文失败或为空 | 保留原题，检查默认可用预设、网络和额度，然后重试；无需重新求解已有方案 |

新建运行会要求模型按所选界面语言输出说明；这不保证提供商的原始推理也使用同一语言。中文题面加中文模式通常无需额外生成阅读译文。

题库翻译和阅读翻译只翻译自然语言，包括表头与单元格说明，要求保留数字、公式、变量名、代码和表格结构。首次生成调用服务端默认可用预设并计入额度；相同原文、目标语言和翻译规则命中本地缓存时复用译文。译文可能有误，重要的单位、否定条件和约束方向仍须与原文核对。

复制、下载、版本文本差异和后续建模使用原始内容。题库中若明确选择“带入译文”，译文会成为新运行的题面，应在提交求解前检查。

## 恢复与问题记录

刷新对话可连接活动运行，已完成方案从卡片或历史打开。停止后可重试原消息；批量场景重试复用已保存项并继续剩余计算。

记录问题时整理以下信息：运行链接、方法、库、后端、预设显示配置、失败阶段、完整错误、相关题面，以及预期结果和实际结果。这样可以把问题直接对应到具体输入与执行路径。分享前去除密钥、许可证和业务敏感数据；不要上传 `.env` 或整个私有工作区。部署日志与工作区备份见[团队维护](../configuration/)。
