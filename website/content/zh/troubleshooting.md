先查看失败阶段和完整错误。区分服务连接、大模型调用、代码执行、模型不可行和方法验证失败，才能选择有效的处理方式。

## 页面或模型服务连接失败

| 现象 | 下一步 |
|---|---|
| 无法连接平台服务器 | 检查 `docker compose ps`、监听端口、防火墙和访问地址 |
| 预设报 401 | 核对密钥、服务商和接口协议 |
| 预设报 404 | 核对接口地址和模型 ID；显示名称不能代替模型 ID |
| TriVAL 与 DeepSeek 结构化输出失败 | 按[预设指南](../model-presets/)关闭运行预设的思考模式 |
| HTTPS 证书失败 | 检查域名解析、80/443 端口与 Caddy 日志 |

## 求解代码或后端失败

找不到 Worker 镜像时，Compose 重新执行 `docker compose up -d --build`；本地服务运行 `uv run llm4om build-worker`。无法访问 Docker 时检查 socket 路径和权限。

后端不可用时，展开具体原因，检查安装程序、接口类型和许可证。显式指定的引擎不会自动替换。连续问题不能送入只支持整数的模型，整数问题也不能直接换成 LP 后端。

## 有最优值但仍提示失败

求解器的最优结论针对当前模型。TriVAL 或 SAC-Opt 的验证仍可能未通过；Feedback Repair 也可能指出目标系数、约束或数据绑定错误。阅读方法反馈与模型版本，不要只看目标值。

新版代码执行前失败时，不会沿用旧版求解结果。之前实际完成的求解仍在“建模过程”中保存。

## 无解、局部结果和用量限制

不可行先核对[冲突证据](../conflicts/)及业务条件。局部最优和局部不可行保留局部含义，详见[CasADi](../casadi/)。每日 token 额度用完时，选择另一可用预设或等到服务器配置时区的次日；不能通过重试绕过额度。

## 恢复对话或提供问题信息

刷新可以重新连接活动运行，文字回复失败不会删除已保存方案。停止后保留过程不等于能从中断节点继续。反馈问题时记录运行链接、失败阶段、方法、库、后端和完整错误；不要附带 API 密钥或许可证文件。
