“通过对话整理需求”把初步想法整理为可编辑的题面和附件。适合已经知道要安排什么，但目标、规则或数据还需要逐步补充的情况。

## 从已有草稿或空白开始

首页填写过的文字和附件会带入需求对话。也可以直接描述场景，例如“我想为三家门店安排下周员工”。助手根据回答更新需求稿，逐轮询问影响下一步的内容。

电脑端左侧保留问题与数据，旁边显示需求助手；窄屏通过页签切换。需求稿可以直接修改，也可切换 Markdown 预览。

## 一份需求稿怎样形成

```mermaid
flowchart LR
  Idea["初步想法"] --> Chat["对话补充目标、规则与数据"]
  Chat --> Draft["更新可编辑需求稿"]
  Draft --> Edit["用户修改与保存"]
  Edit --> Configure["选择方法、库与预设"]
  Configure --> Run["开始建模"]
```

```walkthrough
[
  {"title":"描述任务","nodes":["Idea","Chat"],"body":"先说决定对象、时间范围和希望改善什么。助手据此整理当前信息。","artifact":"为三家门店安排下周员工，希望控制总用工费用。"},
  {"title":"补充关键规则","nodes":["Chat","Draft"],"body":"把回答转成具体规则，并记录仍需补充的数据。","artifact":"每日每店至少3人；每人最多5天；周末需要主管。\n数据：员工费用、可工作日期、主管资格。"},
  {"title":"人工改稿","nodes":["Edit"],"body":"直接修改需求稿中的规则、单位或措辞，保存后继续讨论。","artifact":"补充：跨门店调动允许；同一天每人只去一家门店。\n附件列：员工、日期、可用性、日费用、主管资格。"},
  {"title":"交给建模","nodes":["Configure","Run"],"body":"选择方法、建模库和预设，点击开始建模。方法收到当前题面与附件。","artifact":"交接产物：完整需求稿 + 当前附件\n后续运行保存这一版输入。"}
]
```

## 可复用的题面结构

```text
任务：安排什么对象，覆盖什么时间范围。
决策：需要确定哪些数量、选择或顺序。
目标：最低费用、最大收益，或其他明确目标。
规则：逐条说明必须满足的要求。
数据：文件名、字段含义、单位和行列对应。
```

可以从最熟悉的部分开始填写，助手会继续补充。价格、工时和数量在需求稿中保留明确单位，附件列名也可以直接编辑。

## 保存、搜索与交接

离开编辑区会保存人工改稿，也可点击“保存需求稿”。发送下一条消息和启动建模前，会先保存当前内容；附件读取完成后一起保存。

开启联网搜索后，可查看查询词与来源，选择采用的业务规则并写入需求稿。“用于建模”将当前需求稿带回建模工作区；直接在当前区配置并开始也可以。

## 继续使用

对话历史保留需求演变，运行记录保存交接时的题面与数据。未发送文字保留在当前浏览器标签页，刷新后可以继续起草。停止或失败后可重试这一轮，再继续完善需求。

下一步见[数据上传与编辑](../attachments/)及[运行设置](../run-settings/)；希望把整理与计算放进持续对话，可直接使用 [Chat Agent](../chat-agent/)。
