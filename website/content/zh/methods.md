建模方法决定大模型怎样形成数学模型和代码，以及何时验证、调试或继续搜索。它与大模型预设、建模库和求解后端分别配置。

## 按流程特征选择

第一次体验可以从 Direct 开始；需要求解后复核时看 Feedback Repair。要研究具体机制，可以根据下表进入对应方法。这里按流程分类，不是准确率排名。

| 方法 | 核心流程 | 显式问题范围 |
|---|---|---|
| [Direct](../direct/) | 一次生成模型与代码 | 由方法提示、库和后端共同决定 |
| [Feedback Repair](../feedback-repair/) | 生成、求解、对照原题复核与修正 | 同上 |
| [TriVAL](../trival/) | 语义、数学模型、代码三阶段验证 | 同上 |
| [OptiMUS 0.3](../optimus/) | 分项提取、逐条建模、组装与调试 | LP/MILP |
| [Chain-of-Experts](../coe/) | 协调者依次选专家，汇总建模 | LP/MILP |
| [OptiTree](../optitree/) | 类型树匹配、思路检索、代码检查 | LP/MILP |
| [OR-LLM-Agent](../or-llm-agent/) | 数学模型、代码、执行与复查 | LP/MILP |
| [ORThought](../orthought/) | 建模思路、数学模型、代码与错误调试 | 由方法提示、库和后端共同决定 |
| [LLMOPT](../llmopt/) | 五要素模型与自我校正 | 同上 |
| [AutoFormulation](../autoformulation/) | 组件建树、MCTS、模型排名 | LP/MILP |
| [SAC-Opt](../sac-opt/) | 语义锚点、回译、选择性修正 | LP/MILP |
| [BIND](../bind/) | 数据结构、完整数据绑定、执行修复 | 由方法提示、库和后端共同决定 |
| [OptiMind](../optimind/) | 公开类型提示与多轮反馈 | 同上 |

## 怎样配置和比较

在运行设置中选择方法，或在 Chat Agent 消息中明确指定。13 个内置方法都接受九个建模库，但某个库能否表达问题、后端能否求解，以及方法本身的问题范围仍需同时满足。

参数由部署预设固定，每篇方法文章的参数表从当前代码生成。单次运行不能通过界面、CLI 或 Python 修改这些参数；实际快照保存在运行配置中。用[方法对比](../method-comparison/)可以保持问题与环境不变，检查不同方法的实际行为。

## 研究方法在平台中的含义

平台保留已移植方法的核心编排、提示和停止条件，并记录代码契约与执行环境适配。SAC-Opt 是独立实现；BIND 和 OptiMind 有明确的公开范围与部署适配。各篇文章分别说明，不能把所有方法都描述为逐字移植。

方法使用你配置的 LLM。接入一套推理流程不等于使用了论文训练模型，也不等于复现其评测成绩。每次运行的实际模型、参数、步骤和结果才是检查该次行为的依据。
