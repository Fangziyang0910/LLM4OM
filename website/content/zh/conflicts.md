不可行结果表示当前模型的要求无法同时满足。平台在取得具体求解证据时，将冲突约束关联到业务说明，并提供可继续尝试的调整入口。

## 从哪里查看

运行结束后打开“解”与“为什么无解”。展开“查看对应约束”，可看到解释引用的约束或变量界。数学模型与求解代码仍保留在相邻页签。

线性模型的冲突诊断使用 Gurobi IIS，CPMpy 使用 MUS。结果保存原始证据，便于从业务要求追到数学表达。

## 一个具体冲突

生产问题增加“B至少5件”，同时装配容量为8小时。相关表达为 `B≥5`、`A+2B≤8` 和非负产量。冲突解释可把它们对应到最低订单与装配容量。

```mermaid
flowchart LR
  Model["当前模型不可行"] --> Evidence["IIS / MUS 约束证据"]
  Evidence --> Explain["映射为业务要求"]
  Explain --> Edit["填写候选调整"]
  Edit --> New["用户确认后生成新方案"]
  New --> Compare["查看新结果与原方案"]
```

## 从证据尝试调整

解释区最多给出一项有依据的候选调整。点击“尝试这个调整”，要求进入调整窗口；你可以修改后点击“生成新方案”。平台重新建模并求解，保留原结果。

例如将装配容量改为10小时，保留B至少5件，得到A=0、B=5、收益10。也可以根据业务允许范围更改最低订单量，再计算新方案。

## 根据运行信息继续处理

| 看到的信息 | 可以做的操作 |
|---|---|
| 具体冲突约束 | 对照业务规则，选择要调整的条件 |
| 冲突诊断执行错误 | 查看诊断错误、Gurobi许可与模型规模 |
| 原生局部不可行状态 | 查看初值、边界及原生求解反馈 |
| 代码执行错误 | 打开建模过程，定位语法、数据或接口错误 |

诊断能力由接口提供。CVXPY 路径可查看原始状态和模型，Gurobi线性诊断与CPMpy MUS提供对应冲突证据。配置见[求解后端](../backends/)，模型调整见[调整条件](../revisions/)。
