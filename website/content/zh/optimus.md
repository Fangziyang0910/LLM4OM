OptiMUS 0.3 把问题拆成参数、目标和约束，逐项构建数学表达与代码，再组装执行。平台方法 ID 为 `optimus`。

## 执行流程

```text
参数 → 目标与约束提取 → 约束检查 → 数学表达
     → 逐项代码 → 组装 → 执行 → 必要时调试
```

约束提取包含冗余和置信度检查。组件代码使用所选建模库，最终组装为平台可执行的完整函数。

## 怎样使用

在设置中选择 OptiMUS 0.3。它保留 LP/MILP 范围，适合观察目标与各条约束分别如何形成。参数取值应在题面或附件中明确提供；附带上游格式 `params.json` 时可按该格式使用。

平台支持九个建模库，但不因此把非线性问题改成线性问题，也不会放松变量域。

## 阅读过程与停止条件

检查参数值、每条约束的公式、目标表达和组装代码。执行出错后进入调试，执行次数受预设限制。上游以最优状态作为调试成功条件，因此不可行或无界模型也可能进入调试；阅读它时应与 Feedback Repair 的停止规则区分。

## 来源与平台适配

流程和提示来自 [OptiMUS 固定 v0.3 提交](https://github.com/teshnizi/OptiMUS/tree/e182e9ef5841605c2a7e87467021fd83522b6484)，论文为 [OptiMUS v0.3](https://arxiv.org/abs/2407.19633)。平台关闭人工交互，不启用上游 RAG 路径，并将执行与代码契约接入所选库和沙箱。
