# 插件、产物与求解

字段和版本见[核心契约](../contracts/core.md)、[插件契约](../contracts/plugins.md)及[执行契约](../contracts/execution.md)。

## DD-03 插件接入与兼容路径

Registry 发现内置和已安装工厂，检查键冲突、版本、schema 和依赖。Planner 按本次解析能力建立表示、构建、求解和评测路径。

静态能力通过后，运行时预检确认 Worker、包、求解器和许可证条件。不兼容组合在生成前拒绝。缺失声明表示未知，不隐式替换插件。

宿主和 Worker 固定执行内容、配置和实际依赖。插件更新需要新身份；恢复不能借旧配置静默使用新包。对应 FR-01–06，AC-01/02/21。

## DD-04 建模输出与数据绑定

阶段产物分别保存数学表述和求解实现。ModelArtifact 将其与公开问题、假设、需求溯源和来源关联。最终选择确定建模输出。

原数据先校验原始字节和 schema，视图再记录暴露范围。Formulation 和 Code 绑定同一修订及数据哈希。哈希证明身份，参数/索引映射说明使用关系，两者分别检查。

严格 IR 已展开为确定数值实例。换数据不能直接复用旧绑定；参数化工厂可读取新数据并形成新产物。源模板和数据身份分别记录。

工厂或 MPS 提取视图标明来源，不替换原数学表述。缺阶段明确标为不可用。对应 FR-09/12/20/21/22/26，AC-03/10/24。

## DD-05 编译执行与求解结果

严格 IR 经确定性编译形成后端实现。方法工厂在隔离子进程构建，可信收集器核对导出实例后独立求解。原生脚本的原始执行和可信收集分别记录。

公开输入只读，生成代码无网络、密钥、私有评测材料或宿主写入权限。CPU、内存、进程、时间和输出受限。生成代码不能通过 stdout 或修改模块伪造可信结果。

原始状态、归一化状态、primal、目标、bound/gap 和有效选项分别保存。无解时缺失字段为 null；错误保留阶段产物和实际诊断。模型最优不等于原问题正确。

取消先合作终止，再有界清理。daemon 不可达时保存实际清理失败，不声称容器已删除。对应 FR-21–29，AC-10/11/12/13/14/24。
