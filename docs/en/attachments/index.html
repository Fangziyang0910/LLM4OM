User guides/Upload and edit data

Upload and edit data

Review spreadsheets, fields and units before computing with the full data.

On this page
Prepare files and descriptionsWhat to inspect in the editorTry saving and cancellingHow data reaches the modelWatch the actual workflow

Attach Excel, CSV, TSV, JSON or text files so generated code can use complete data. Click a file name to inspect fields, edit cells or raw text, and save the attachment to the current problem.

Prepare files and descriptions#

Each uploaded file supports up to 2 MB. Every Excel worksheet becomes a CSV. Common file-name characters are preserved. Describe file names, fields, units and index mappings in the problem.

For production.json, explain that usage rows identify resources and columns identify products, measured in hours per unit, with nonnegative integer production quantities.

Download the ready-to-use JSON example and CSV example.

What to inspect in the editor#

DataExample action
Headers and unitsChange “Price” to “Unit profit (CNY)”
IdentifiersPreserve store IDs such as 001 as text
ValuesEdit costs, demands or available hours
Matrix orientationMatch rows to warehouses and columns to stores
StructureEdit JSON as raw text; switch tables to raw view

Tables display 50 rows per page while retaining the complete data. Use raw view above 50 columns. Saving validates CSV quoting and JSON syntax so errors can be corrected in the editor.

Try saving and cancelling#

Change cutting capacity from 8 to 10 hours, choose “Save data,” then “Start modeling.” Profit changes from CNY 13 to 16. “Cancel edits” restores saved values; the original snapshot retains the first plan's inputs and profit.

Try editing dataINTERACTIVE

A earns CNY 3 per unit and uses 2 cutting hours and 1 finishing hour; B earns CNY 2 and uses 1 and 2 hours. Save the edited hours, then start modeling to calculate whole-unit quantities.

Run result (8 / 8 hours): A = 3, B = 2, profit CNY 13.

A fixed teaching example, computed instantly in your browser.

In the workbench, “Save data” applies attachment edits. Modeling uses the current saved inputs; existing runs retain their original data for comparison.

How data reaches the model#

data maps file names to text, parsed during execution. For large structured attachments see BIND: generation receives structure and execution reads full values.

Watch the actual workflow#

Choose “Edit data” below the recording to jump to opening an attachment, editing unit profit and saving it. See quickstart for the complete workflow.
