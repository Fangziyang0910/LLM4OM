Modeling methods/LLMOPT

LLMOPT

Construct a five-part formulation and route corrections to the affected stage.

On this page

LLMOPT connects language and code through a five-part formulation: Sets, Parameters, Variables, Objective and Constraints. After execution, self-correction judges the formulation and code separately and returns to the affected stage.

How five elements locate errors#

The structure separates objects, known quantities, decisions, goals and requirements. Indices, units and domains have explicit places, making it easier to distinguish a modeling error from an implementation error.

ElementProduction example
SetsProducts P={A,B}; resources R={cutting,finishing}
ParametersProfit p, consumption matrix a, capacity b
VariablesNonnegative integer quantities x[p]
ObjectiveMaximize total profit
ConstraintsResource use cannot exceed each capacity

Workflow and correction example#

FOLLOW THE EXAMPLE
1. State structure

Preserve whole-unit requirements, resource dimensions and parameter values. F2C depends on this formulation, so omissions can propagate into code.

Sets: P, R
Parameters: profit[P], usage[R,P], capacity[R]
Variables: x[P] are nonnegative integers
2. Translate to code

Build the native model from the five elements, then execute. Check corresponding variables, objective and resource constraints.

Objective: max Σ profit[p]x[p]
For each r: Σ usage[r,p]x[p] ≤ capacity[r]
3. Choose the return point

If the formulation made quantities continuous, rebuild it and code. If only code uses the wrong domain, regenerate code alone.

Wrong formulation → Q2F → F2C → solve
Only code wrong → F2C → solve
4. Read final evidence

Use the last execution for numerical evidence. The run retains correction judgments alongside execution status.

Up to 12 re-solves after the first execution.
Final result uses the last actual execution.

Worked example: illustrative inputs and intermediate artifacts.

What self-correction reads#

The judge receives the original problem, five-part formulation, code and actual feedback: status, errors, objective and decision values.

The platform routes a wrong formulation to Q2F first; otherwise wrong code returns to F2C. Upstream did not publish the complete loop code, so routing follows the paper's description. Missing judgments currently parse as correct, making inspection of the actual judgment text useful.

Workflow versus trained model#

The paper also includes multi-instruction SFT and KTO alignment. This platform integrates the inference workflow using the selected LLM preset.

To use released weights, deploy them separately behind a compatible service and add an openai_compatible preset. Changing orchestration and changing weights are separate experimental conditions.

When to use it and what to inspect#

Use it for a structured formulation checkpoint and stage-specific correction. The method is not uniformly restricted to linear models; library and backend capabilities still apply. Inspect indices and domains first, then whether correction returns to the right level.

Source and platform adaptation#

Based on the pinned LLMOPT implementation and paper. It retains Q2F/F2C and correction prompts with native-model contracts. The loop follows the paper and returns the last execution.

Current parameters#

Parameters come from the deployed method preset. They are saved with each run and cannot be changed per run in the UI, CLI or Python API.
