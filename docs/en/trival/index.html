Modeling methods/TriVAL

TriVAL

Validate semantics, formulation and code, with revisions across stages.

On this page
What each level checksWorkflow and worked exampleHow validation failures are routedReading a run effectivelyRequirements and budgetRelated methods and implementationCurrent parameters

TriVAL separates three questions: was the problem understood correctly, does the formulation express that understanding, and does the code implement the formulation? Each level has construction, validation and revision. A code-stage finding can send the workflow back to the formulation.

What each level checks#

LevelArtifactsExample failureRevision
SemanticsFacts, ambiguities and resolutionsInterpreting coverage per shift as a daily totalExtract facts again or revise ambiguity resolutions
FormulationParameters, indices, variables, objective and constraintsMissing per-shift coverage or reversing a minimumRevise locally or rebuild the formulation
CodeNative model code and execution evidenceWrong indices, domains or implementationRepair code, or return to the formulation if that is the cause

This distinction puts repair where the error originated. Code that faithfully implements a wrong formulation will not improve through syntax fixes alone.

Workflow and worked example#

FOLLOW THE EXAMPLE
1. Semantic facts

Separate profits, processing times, resource limits and whole-unit requirements. An additional requirement of at least 3 units of B must remain a demand fact.

Facts: whole products; 8 hours of each resource; B at least 3.
Check interpretation: unit net profit and processing hours per unit.
2. Formulation

Parameter/index, variable, objective and constraint experts construct in parallel. A selector assembles the formulation, which is checked against the facts.

max 3A + 2B
2A + B ≤ 8; A + 2B ≤ 8; B ≥ 3
A, B are nonnegative integers
3. Execute and attribute

If code omits B ≥ 3 but the formulation includes it, repair code. If the formulation also omits it, return to that level.

Implementation omission → repair build_model(data)
Formulation omission → revise formulation, then regenerate code
The routes address different causes.
4. Report separately

The correct integer optimum is 12. The final record shows numerical results and each stage's validation status.

Solver evidence: A = 2, B = 3, objective 12
Record semantic / formulation / code validation separately
Stage feedback records the final validation decision.

Worked example: illustrative inputs and intermediate artifacts.

How validation failures are routed#

Semantic checks distinguish faithful facts, relevant ambiguities and consistent resolutions. Faulty facts or ambiguity identification cause extraction again; inconsistent resolutions return to ambiguity resolution. Formulation checks can request partial revision or a new construction by the experts.

Code is executed before code validation. Attribution to the formulation sends the outer workflow back to that level. An upstream stage can proceed with its latest artifacts after reaching its limit. The platform reports each unpassed stage at exit.

Reading a run effectively#

Choose a rule that is easy to misinterpret and follow it through facts, formulation and code. For “each employee works at most five days,” check for an employee index with a separate constraint for each employee. Then inspect whether later artifacts actually address the validator's finding.

The run retains solver values and stage validation feedback. Comparisons can inspect status, failed stages, revisions and actual call usage.

Requirements and budget#

Select TriVAL and a library/backend supporting the intended mathematics. Each stage allows at most five validations; code execution allows twenty attempts. Total LLM use depends on nodes and return paths.

For DeepSeek, forced tool choice requires thinking mode to be disabled in the preset: {"thinking":{"type":"disabled"}}. See LLM presets.

Related methods and implementation#

Feedback Repair reviews the model after solving; TriVAL moves checks into separate levels. SAC-Opt focuses on the consistency of backtranslated constraint code.

The platform ports the pinned SCUT-EIPI/TriVAL implementation, retaining its graph, nodes, prompts and loops. It supplies the LLM and sandbox, maps input and reports unresolved validation at exit.

Current parameters#

Parameters come from the deployed method preset. They are saved with each run and cannot be changed per run in the UI, CLI or Python API.

ParameterValue
max_validations5
max_code_executions20
