How modeling works

Understand methods, LLMs, modeling libraries, solvers and saved runs.

On this page
Run data flowFour configuration objectsFour types of model informationRuns and plansCommon statuses

LLM4OM connects requirements, modeling, computation and plan management. These terms map to settings and artifacts in the workbench.

Run data flow#

Attachments map file names to complete text. build_model(data) parses inputs and returns a native model. The platform executes and retains results.

Four configuration objects#

TermRoleExample
MethodGeneration, checking and repair orchestrationDirect, TriVAL, BIND
LLM presetService and request configurationTeam endpoint and model ID
LibraryVariables, objective and constraintsPyomo, CPMpy, CVXPY
BackendMathematical computationHiGHS, CP-SAT, Gurobi, Ipopt

One configuration might be “Feedback Repair + team preset + Pyomo + HiGHS.” Run information retains selections and the actual engine.

Four types of model information#

InformationMeaningProduction example
ParametersKnown input valuesUnit profit and capacity
VariablesQuantities or choices to determineA and B quantities
ObjectiveExpression to minimize or maximizeTotal profit
ConstraintsRelationships decisions must satisfyHours and minimum orders

Indices extend these objects across products, dates, employees and nodes. Units connect statements, data and result labels.

Runs and plans#

A run contains inputs, settings, steps, formulation, code and execution. A plan is its computed decision result. Revisions create new runs; scenarios connect runs to one baseline. The conversation's current plan determines the basis for questions and changes.

Common statuses#

StatusMeaning
optimalOptimal result for the current model
feasibleA feasible plan is available
locally_optimalLocal result from a native nonlinear path
infeasibleCurrent requirements cannot hold together
unboundedObjective is unbounded along a feasible direction
time_limitLimit reached; inspect retained solution and feedback
Execution or validation failureRead the specific stage and feedback

Status, values and method validation remain in the run. See results for daily use and methods or solvers for mechanisms and interfaces.
