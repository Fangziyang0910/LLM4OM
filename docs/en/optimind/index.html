Modeling methods/OptiMind

OptiMind

Combine public problem-type hints with multi-turn solver feedback.

On this page

OptiMind combines public problem-type hints with multi-turn solver feedback. A successful solve still produces feedback, allowing another revision or a final textual answer that ends the trajectory.

What the hint library provides#

Type hints highlight common modeling mistakes. In traveling salesperson models, one incoming and one outgoing edge per city can still produce separate subtours; additional constraints must enforce a single tour.

The public library currently contains only TravelingSalesman, with six error/hint pairs. Classification selects a public type or no match. Unmatched problems receive general checking guidance.

Workflow and checking example#

FOLLOW THE EXAMPLE
1. Match hints

Traveling salesperson problems can use public specialist hints. Other types use general checks when no public entry matches.

Example: visit every city once and return to the start.
Reminder: in-degree/out-degree constraints do not eliminate separate subtours.
2. Generate and solve

The generator turns hints into constraints; the process retains both the hint and generated formulation.

Inspect binary edges, degree constraints and subtour elimination.
Actual solver execution provides the numerical result.
3. Check success too

Read selected edges even after optimality. Separate cycles identify a connectivity rule to inspect.

Two disjoint cycles → inspect connectivity constraints.
Faithful model and result → final answer can end the run.
4. End one trajectory

The default follows one trajectory without majority voting. A code-free final answer preserves the last executed result.

At most 5 generations; temperature 0.6; top_p 0.95.
Textual completion does not replace execution.

Worked example: illustrative inputs and intermediate artifacts.

Revision and stopping#

Feedback includes successful as well as failed statuses, objectives and values. Revised code continues the generate–execute–feedback loop. After a valid execution, a final reply without code can stop it.

Without any valid execution, a code-free reply is not completion; code is requested again within the budget. Final numbers come from the last executed model, not the final prose.

Comparing related workflows#

Feedback Repair has an explicit accept-or-repair review. OptiMind centers on hints and continuing feedback within one trajectory. OptiTree retrieves entries from a hierarchical type tree, a different source and use of guidance.

Use it to inspect the effect of public hints. The current registry does not impose a uniform linear-only restriction; library, backend and hint scope still apply. Weights, orchestration and specialist hints are separate experimental conditions.

Public scope and platform implementation#

Based on the pinned Microsoft OptiGuide/optimind implementation. The platform preserves public hint files, adds optional type matching and supplies native-model contracts and actual solver feedback. The public hint files and adaptation are available in source.

Current parameters#

Parameters come from the deployed method preset. They are saved with each run and cannot be changed per run in the UI, CLI or Python API.
