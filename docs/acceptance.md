# 1.0 验收清单与需求追踪

以下复选框用于完整 1.0 验收，目前仍未全部通过。S01 已完成 AC-03/08/19/23 的离线工程部分，证据见 [S01 实现记录](development/s01-offline-run.md)；真实求解、隔离、恢复和 Web 不计为已完成。

文档修订：0.4.0。验收覆盖单问题两阶段建模、数据绑定与研究来源；详细流程见 [详细设计](detailed-design.md)。

## 1. 测试分层

- 契约层：Manifest、数据对象、配置、能力匹配和错误语义；不访问真实云服务。
- 确定性层：自建问题、Mock、真实 HiGHS、编译语义、独立检查器。
- 系统层：容器权限、并发、取消、崩溃恢复、CLI／Web 与报告。
- 外部层：通用外部 LLM、真实 Gurobi 和固定版本 OptiMUS／CoE；记录日期、环境、模型、依赖、凭据可用性与使用量。

外部条件缺失允许显示 skip，但不计作已验证支持。最终发布证据必须覆盖产品宣称的全部 MUST 能力。

## 3. 编译与评测的必需微型 fixture

- [ ] MILP 示例：A/B 整数非负，`2A+B≤8`、`A+2B≤8`，max `3A+2B`，最优 A=3、B=2、目标 13。
- [ ] LP 松弛：相同约束，连续域，A=B=8/3、目标 40/3。
- [ ] 目标常数：上述目标加 7，MILP 最优值 20，决策不变。
- [ ] 最小化与负目标：目标方向和常数保留，不通过取绝对值匹配参考。
- [ ] 约束常数：`A+1≤4` 等价 `A≤3`，编译不能变成 `A≤5`。
- [ ] 域与界：binary、整数实数边界、null 界、lower>upper、重复 ID、NaN 拒绝。
- [ ] 多最优解：不以解向量与某个参考解完全相等作为唯一成功条件。
- [ ] infeasible：A≥2 且 A≤1；unbounded：max A 且 A≥0，无上界。
- [ ] 遗漏域：用 LP 解冒充要求整数的原问题，候选 optimal 但独立检查失败。
- [ ] 遗漏约束：删除一个资源约束，代码成功但独立业务可行性失败。
- [ ] 目标偶合：要求 A≤1，候选允许 A≤2，目标恒为 0；目标一致仍不证明模型等价。
- [ ] 目标数值相同但单位不同：未声明的缩放映射不自动修正。
- [ ] 利润绑定交换：候选 max 2A+3B 得 A=2/B=3、自报 13；原目标 3A+2B 为 12。独立可行检查通过，但原目标质量检查失败。

- [ ] 原 Formulation 正确但 Code 错系数；Code 忠实实现错误 Formulation；两类失败的来源分别记录。
- [ ] 一次调用联合输出两阶段，阶段轨迹共享 call_id，账本只记一次；修改 Formulation 后旧 Code 不复用。
