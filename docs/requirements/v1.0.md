# 产品需求规格

本页维护产品范围和稳定 FR/NFR 编号。MUST 表示必须满足的要求。实际可用能力见 [README](../../README.md)，验证边界见[支持验证](../development/validation.md)。

## 产品与范围

LLM4OM 面向希望用自然语言解决优化问题的使用者。输入描述与可选业务数据，选择 LLM、方法和求解器，查看建模过程、数学模型、代码和结果。

Formulation 表达数学含义，Code 提供计算实现，Solve 随后执行。五元素是默认表述方式。方法可联合生成或往返修正，实际步骤由方法决定。

当前开发范围是本机后端和单用户 Web，可靠执行范围为 LP/MILP。七种内置方法通过声明接口组合 LLM、后端和求解器。研究方法集成编排和提示思路，完整论文复现及专用训练权重不作为接入要求。

平台维护内置 Benchmark 公开题面，支持逐条浏览、复制和带入建模。CLI/SDK 提供插件接入、冻结数据导入和批量评测，与 Web 共用应用流程。

公网多人部署、多平台适配、非线性优化、CP、模型训练和新数值求解器不属于当前范围。正式 1.0 发布另按[验收清单](../acceptance.md)核对。

## 使用场景

| 场景 | 用户行为与结果 |
|---|---|
| 单问题建模 | 输入目标/规则/数据，获得阶段产物与求解结果，无需参考答案 |
| 过程检查 | 查看真实步骤和诊断，回答澄清或创建派生版本 |
| 样例试用 | 浏览内置题面，复制或带入后主动开始求解 |
| 方法扩展 | 独立插件声明配置、能力和来源，不修改调度内核 |
| 研究比较 | 固定样本/模型/预算/协议，保留失败和逐样本证据 |

## 功能需求

| ID | 优先级 | 要求与可观察结果 |
|---|---|---|
| FR-01 | MUST | 统一插件 Manifest，声明种类、插件 ID、版本、契约范围、能力、配置结构与依赖。错误版本在执行前拒绝并定位字段。 |
| FR-02 | MUST | 从内置注册及已安装的 entry points 发现插件；第三方插件不修改核心即可列出、预检、运行。重复 ID 不静默覆盖。 |
| FR-03 | MUST | 方法、LLM、任务、数据、编译、建模后端、求解器、评估器、执行器、产物存储、报告器有明确接口；不强迫每次运行使用全部接口。 |
| FR-04 | MUST | 能力匹配必须校验产物类型、问题类型、建模后端、求解器、LLM 功能、隔离环境和评测证据。未知／不兼容能力产生确定原因；不得隐式替换。 |
| FR-05 | MUST | 配置分别校验方法与 Provider。Web 提供固定供应商预设和自定义兼容地址，支持读取模型目录及手动填写。模型和密钥按端点私有保存，刷新/重启后恢复，页面显示掩码。细则见 [Web 契约](../contracts/web.md)。 |
| FR-06 | MUST | `plugins list` 和 `doctor` 显示插件能力、配置错误、缺失依赖、许可证／模型连通性检查结果；连通性检查需显式启用，不能默认产生付费调用。 |
| FR-07 | MUST | ProblemSpec 支持原始描述、语言、问题类型提示、需求条目、数据引用、假设与 revision；保留未经改写的来源。文本即可发起任务，requirements 可空、类型可 unknown，不能强制用户先完成结构化建模。 |
| FR-08 | MUST | TaskAdapter 把来源拆成公开 ProblemSpec 和隐藏 EvaluationOracle；运行方法无权访问 oracle、参考模型或参考目标。 |
| FR-09 | MUST | CSV／JSON 加载器校验路径、类型、键、缺失值、重复行及文件大小，给出行列级错误；生成文件校验和。不得无记录填补业务缺失数据。 |
| FR-10 | MUST | 数据集记录来源、许可、原始 ID、版本、split、内容哈希、清洗理由；相同问题的不同清洗版不得混合成一个结果。 |
| FR-11 | MUST | Web 随包提供平台维护的 Benchmark 公开题面；直接复用 OPT-Agent 管理器的公开输入，逐条浏览、复制或带入单问题建模，保留已选方法与求解器。维护端记录来源版本与哈希，不将参考答案或参考代码放入题面包。原有 CLI Task／Evaluation 导入与评测接口独立保留。 |
| FR-12 | MUST | 跨模块数据引用通过 ArtifactRef 与受控读取；大表格只按允许的行／列／摘要读取，并记录暴露给 LLM 的数据视图。 |
| FR-13 | MUST | 方法接口接收公开问题及受预算约束的 Context，输出建模输出／待输入／失败；建模步骤、调用和阶段产物父子关系可追踪。 |
| FR-14 | MUST | 七种内置方法记录实际编排、阶段产物、修正、选择和来源。研究方法保留核心编排与提示，记录通用 LLM、代码目标及原工作条件的差异。流程变体不冒充原训练模型复现。 |
| FR-15 | MUST | Provider 声明并校验实际请求能力，统一文本、响应、用量和错误。不支持的功能在生成前拒绝。 |
| FR-16 | MUST | OpenAI-compatible 可配置端点与模型，包括支持该协议的本地部署；Anthropic 使用独立适配器。远程调用包含超时、取消、限流与有界重试。 |
| FR-17 | MUST | 统一预算限制 LLM 调用／token、公开检查、修正轮数、求解次数、墙钟时间与并发；实际重试计入资源消耗，不通过重试绕过预算。 |
| FR-18 | MUST | 支持固定模型与预算的方法比较和按角色配置模型；报告中将同模型比较与异构模型组合比较区分。 |
| FR-19 | MUST | 方法可以提出结构化澄清请求；交互暂停后可恢复。批量无交互时以 `unresolved` 记录，不用 oracle 或 LLM 臆测补齐后仍声称原题已解决。 |
| FR-20 | MUST | 建模输出关联独立 Formulation/Code、阶段可用性、假设、数据绑定、需求溯源和来源。默认五元素，严格 IR 与提取视图分别标识。缺失信息如实记录。 |
| FR-21 | MUST | IR 采用版本化 LP/MILP 结构，变量域、边界、线性目标、约束、常数与来源明确；非法变量引用／非有限值／非线性结构执行前拒绝。 |
| FR-22 | MUST | IR→Pyomo 编译是确定性转换，单独验收语义保持；不依赖 LLM 二次改写。Code 可由方法生成或严格 IR 确定性编译得到，均记录来源与表述引用。原生代码可直接走对应 Backend，不要求可靠提取完整 IR。 |
| FR-23 | MUST | 工厂代码采用明确入口构建模型；原生代码适配声明支持组合与结果抽取能力。平台不把 gurobipy 自动宣称为可切换到 HiGHS。 |
| FR-24 | MUST | SolverBackend 标准化原始状态、可行解、目标值、best bound、gap、耗时和终止原因；time limit 下有解与无解不同，infeasible 与 unbounded 不合并。 |
| FR-25 | MUST | HiGHS、Gurobi 和 OR-Tools/SCIP 路径通过真实微型 LP/MILP 验证。缺少可选依赖不阻止兼容路径，不能伪造结果。 |
| FR-26 | MUST | 保存模型、代码、编译映射、求解日志、归一化结果与数据哈希；人工作出的修改形成新 revision／派生运行并记录父记录。 |
| FR-27 | MUST | 生成代码默认在无网络容器执行，无 LLM 密钥、oracle 或宿主写入权限；限制时间、CPU、内存与输出，停止时清理子进程。 |
| FR-28 | MUST | 基准评估在建模完成之后由独立 Evaluator 执行，公开反馈与隐藏评分分开；相同原始答案不得在修正提示中泄漏。 |
| FR-29 | MUST | 分别输出 Formulation 检查、Code 检查、执行、模型自身可行性、独立可行性、目标值匹配与语义证据；无对应 oracle 的检查标记 `not_available`。 |
| FR-30 | MUST | 对所有已纳入评测样本输出结果，明确分母、失败类型、排除原因与统计协议；费用未知不得填写零。 |
| FR-31 | MUST | 配置实验矩阵：任务／方法／模型／后端／重复次数／预算；不支持的组合预检报告并要求明确的排除配置。 |
| FR-32 | MUST | 记录配置、插件/协议版本、方法变体、提示/数据/代码哈希、实际模型、调用、步骤和阶段产物。联合调用计一次用量。回放与新运行分别标明，同名 Benchmark 按来源和版本区分。 |
| FR-33 | MUST | 运行可取消并隔离失败。恢复复用已保存响应和结果；未知请求不自动重发，保留未知状态及预算预留。 |
| FR-34 | MUST | 导出 JSONL／CSV 逐样本结果和 Markdown／HTML 报告；包含能力覆盖、运行失败、证据级别、预算、时间和成本可用性。 |
| FR-35 | MUST | CLI/SDK/Web 共用应用流程，支持单问题配置、过程/产物/结果、取消和恢复。批量实验通过 CLI；已有 HTTP 接口保留，Web 页面围绕单问题。 |
| FR-36 | MUST | 提供离线 Mock 和自建微型任务、插件契约套件及完整流程示例；Mock 输出有标识，不进入真实方法准确率排名。 |

## 非功能需求

| ID | 要求 | 验收口径 |
|---|---|---|
| NFR-01 | 可扩展 | 新增独立方法／Provider／任务／求解器不修改调度内核；至少一个第三方方法包在独立安装环境演示。 |
| NFR-02 | 可复现 | 固定输入、Mock、IR 编译与求解 fixture 可以重复得到同一结构及容差内结果；真实 LLM 不承诺 bitwise 确定性。 |
| NFR-03 | 可观测 | 每个阶段都有结构化事件、关联 ID、阶段耗时和错误；报告能定位一次失败到具体建模步骤与依赖。 |
| NFR-04 | 隔离 | 容器模式阻止 fixture 中的越界文件读写与网络访问，OOM／timeout 不使调度器退出；明确列出测试的威胁范围。 |
| NFR-05 | 性能 | 在记录的 Linux 4 vCPU/8 GiB、并发 4 参考条件下，1000 个离线短任务无丢失，调度附加时间 P95 ≤ 500 ms。LLM、首次容器启动和求解分别统计。该目标按性能任务验证。 |
| NFR-06 | 稳定性 | 100 个任务批次含异常、限流、超时、取消及恢复，其他任务正常完成，终态／预算／产物无重复或错配。 |
| NFR-07 | 可移植 | 核心与CLI使用Python 3.11／3.12，当前按本机Linux验收。其他平台适配留待具体需求，不增加当前开发门槛。 |
| NFR-08 | 依赖可控 | 可选集成依赖按需安装；安装核心与 HiGHS 路径不要求商业许可证或所有厂商 SDK。Messages 当前使用标准库 HTTP，无 Anthropic SDK 依赖。 |
| NFR-09 | 可理解 | 中文主文档、英文接口；报告明确执行模式、证据限制和失败原因；密钥不进入配置导出、日志或异常。 |
| NFR-10 | 版本校验 | Manifest、数据对象、IR、事件和评测协议分别版本化。不支持的版本提前拒绝，指标由协议版本固定。 |
| NFR-11 | 可维护 | 契约套件、确定性 fixture、集成测试与真实外部测试分层；外部不可用报告 skip／原因，不能抹除失败。 |
| NFR-12 | 开源准备 | 记录第三方来源、上游提交、许可与数据使用范围；正式引入代码前完成许可证兼容检查，不能从论文表格推断可复制权利。 |

## 输出与验收

最低输出是可检查的 RunBundle。失败、取消或等待输入也保留已产生的公开产物。无参考材料仍可完成建模和求解，独立检查标为不可用。

发布不预设任意模型准确率门槛。兼容性、执行、真实外部接入和科研准确率分别验证。接口与来源见[文档导航](../README.md)，测试方法见[测试指南](../development/testing.md)。
