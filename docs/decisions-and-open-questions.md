# 设计决策、默认值与待定项

记录日期：2026-10-08。本文区分用户要求与本次需求分析采用的工程默认值；待定项不阻止按当前基线开工，也不意味着需要逐项重新请求许可。

## 1. 用户明确要求

- 通用开源自动优化建模集成平台，作为通用智能优化平台 1.0。
- 集成多种建模方法、LLM、求解后端和基准评测。
- 方法、任务／数据、产物等都有通用抽象层与可插拔接入。
- 本次创建 GitHub 私有仓库、命名平台、完成详细需求分析并提交；后续按文档开发。

## 2. 本次采用的可调整默认值

| 决策 | 当前基线 | 理由／改变的影响 |
|---|---|---|
| 名称 | FormuMesh／formumesh | Formulation＋Mesh，强调连接不同建模方法；技术名称搜索未发现同名 GitHub 仓库 |
| 文档语言 | 中文主文档、英文接口与标识符 | 与讨论语言一致，同时便于代码和插件协作 |
| 首批用户 | 研究者与平台／方法开发者优先 | 用户强调 LLM4AD 式集成与统一评测；业务用户交互仍通过 Web 保留 |
| 可靠执行范围 | LP/MILP | 易形成独立验证与后端互换；新增问题类型使用扩展契约 |
| 首批方法 | direct／feedback_repair／optimus | 两个受控 baseline 加一个论文方法，验证方法可插拔与原生接入 |
| 表示方式 | IR 与原生代码共存 | 防止强制 IR 改变已有方法；表示差异通过能力匹配暴露 |
| 首批后端 | Pyomo＋HiGHS，Pyomo／gurobipy＋Gurobi | 一条开放运行路径与一条广泛研究原生路径 |
| LLM | OpenAI-compatible／Anthropic＋Mock | 验证独立协议 Adapter，本地模型可经兼容端点使用 |
| 基准 | NL4Opt／IndustryOR | 学术与工业场景各一，优先验证来源和参考材料 |
| 入口 | SDK／CLI＋本地单用户 Web | 共用核心；先完成内核再搭界面 |
| 存储 | 本地文件与事件，索引可 SQLite | 降低初始部署成本；存储接口允许后续替换 |
| 许可证 | Apache-2.0 | 适合开放插件协作；未来第三方接入单独核对兼容性 |
| 可见性 | GitHub private | 直接遵从本次请求；开源准备不自动公开仓库 |

## 4. 开发中需验证的事项

| 事项 | 默认行动 | 最迟确定切片 |
|---|---|---|
| OptiMUS 选哪个上游版本／分支 | 检查论文与源码，选可忠实接入版本，固定提交并记录差异 | S06 |
| 真实模型、端点与实验额度 | 不硬编码厂商模型和在线价格；从本地配置读取，先做小规模真实验收 | S05/S08 |
| Gurobi 许可证与容器可用性 | 在可用环境真实验收；缺失时不宣称已验证该路径 | S04/S06 |
| NL4Opt／IndustryOR 原始或清洗版 | 锁版本、保留 ID 和理由，避免跨版本混比较 | S07 |
| 数值容差 | 先使用默认建议，数据源精度确有差异时预先版本化 | S07 |
| Web 技术 | 默认轻量本地工作台，具体框架选择不改变 SDK 契约 | S09 |
| 首份真实实验规模 | 明确可用预算后冻结样本选择；pilot 与全量分开命名 | S08 |
| 公开仓库与对外发布 | 当前保持 private；实现完成后再决定发布日期与可见性 | S10 之后 |

## 5. 范围调整规则

若增加非线性、更多公开方法或托管部署，先更新范围、契约、能力矩阵、评测协议和验收项；不能只添加插件名字就声称已支持。用户后续明确指令优先于本基线。常规库选择和实现修复不需要额外审批。
