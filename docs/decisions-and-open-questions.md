# 设计决策、默认值与待定项

记录日期：2026-10-08。本文记录当前确认的目标、工程默认值与实现时需要验证的条件。常规实现选择按已授权范围执行。

## 1. 用户明确要求

- 通用开源自动优化建模集成平台，作为通用智能优化平台 1.0。
- 集成多种建模方法、LLM、求解后端和基准评测。
- 方法、任务／数据、产物等都有通用抽象层与可插拔接入。
- GitHub 仓库保持 private，未来按开源协作方式组织。
- 名称 **LLM4OM** 采用与 LLM4AD 对应的缩写方式。
- 2026-10-14明确 Web 面向普通使用者；核心用例是自然语言问题经指定方法形成建模输出并调用所选求解器。内置 Benchmark 直接复用 OPT-Agent 已整理的全部题面，支持逐条浏览、复制和带入建模；无需使用者上传数据集或配置实验。开发与批量评测仍可使用 CLI／SDK。
- CLI 与 Web 可视化工作台均为正式入口；同类模块有共同抽象，按职责分别定义方法、输出、求解与评测接口。
- 需求说明、需求分析、架构与详细设计兼顾软件工程和领域论文表述；详细整理代表性方法、benchmark、论文、代码与参考链接。
- 全仓库采用 Matt Pocock 技能所推荐的领域建模、纵向任务、公共入口测试和按需文档方式；GitHub Issues 与五种默认 triage 标签已确认。操作约定见 [issue tracker](agents/issue-tracker.md)和 [label mapping](agents/triage-labels.md)。
- 2026-10-14当前开发交付只要求本机后端与Web能启动、展示并继续开发。复用已有接口，聚焦验证受影响路径；公网多人部署、多平台适配和正式发布不作为本轮收尾条件。

## 2. 已确认设置与可调整的工程默认值

| 决策 | 当前基线 | 理由／改变的影响 |
|---|---|---|
| 名称（用户已选择） | LLM4OM／llm4om | Large Language Models for Optimization Modeling；仓库名 LLM4OM，Python 包／命令／插件命名空间 llm4om |
| 文档语言 | 中文主文档、英文接口与标识符 | 与讨论语言一致，同时便于代码和插件协作 |
| Web 用户（用户已确认） | 普通使用者 | 产品交互围绕自然语言问题、结果和内置样例试用；平台负责维护数据 |
| 可靠执行范围 | LP/MILP | 易形成独立验证与后端互换；新增问题类型使用扩展契约 |
| 首批方法（用户已确认优先经典方法） | direct／optimus／coe；feedback_repair 可选 | 工程对照加 OptiMUS／CoE，保留策略和真实阶段来源 |
| 建模阶段与表示（用户已确认） | Formulation → Code；默认五元素；严格 IR 与原生实现共存 | 分开数学含义与计算实现；联合生成和阶段修正由方法决定 |
| 首批后端 | Pyomo＋HiGHS，Pyomo／gurobipy＋Gurobi | 一条开放运行路径与一条广泛研究原生路径 |
| LLM（用户已确认） | 通用外部 LLM 为主，OpenAI-compatible／Anthropic＋Mock | 暂不集成任务专用训练权重；未来微调模型走同一接口，流程适配另作变体 |
| 基准（用户已确认） | NL4Opt／NLP4LP／MAMO 的 LP/MILP 子集 | NLP4LP 名称已确认；MAMO 保留 EasyLP／ComplexLP，ODE 不纳入 |
| 入口（CLI/Web 已确认） | Python 应用接口／SDK＋CLI＋本地单用户 Web | CLI/Web 共用核心；SDK 与本地单用户部署是工程选择 |
| 存储 | 本地文件与事件，索引可 SQLite | 降低初始部署成本；存储接口允许后续替换 |
| 许可证 | Apache-2.0 | 适合开放插件协作；未来第三方接入单独核对兼容性 |
| 可见性 | GitHub private | 遵从用户要求；开源准备不自动公开仓库 |

## 4. 开发中需验证的事项

| 事项 | 默认行动 | 最迟确定切片 |
|---|---|---|
| OptiMUS／CoE 接入版本、流程与授权 | 优先考察 optimus-v0.3；依据固定提交考察记录复核正式接入，保存论文 revision、检索材料、CoE 输入材料来源、许可与外部模型差异 | S06 |
| 真实模型、端点与实验额度 | 不硬编码厂商模型和在线价格；从本地配置读取，先做小规模真实验收 | S05/S08 |
| Gurobi 许可证与容器可用性 | 在可用环境真实验收；缺失时不宣称已验证该路径 | S04/S06 |
| NL4Opt／NLP4LP／MAMO 原始或派生版 | 锁版本、保留 ID 和理由，避免跨版本混比较 | S07 |
| 五元素到严格 IR 的关联 | 先用人工 fixture 记录同一问题；不声称已解析或编译自由文本 | S01/S02 |
| 数值容差 | 先使用默认建议，数据源精度确有差异时预先版本化 | S07 |
| Web 技术 | 默认轻量本地工作台，具体框架选择不改变 SDK 契约 | S09 |
| 首份真实实验规模 | 明确可用预算后冻结样本选择；pilot 与全量分开命名 | S08 |
| 公开仓库与对外发布 | 当前保持 private；实现完成后再决定发布日期与可见性 | S10 之后 |

## 5. 范围调整规则

若增加非线性、更多公开方法或托管部署，先更新范围、契约、能力矩阵、评测协议和验收项；不能只添加插件名字就声称已支持。用户后续明确指令优先于本基线。常规库选择和实现修复不需要额外审批。

开发默认值在实际接入时验证并锁定。文档整理与资料增长不自动扩大发布范围；变更结果由 [规格校验](spec-validation.md)和 [整理记录](repository-audit.md)维护。
