# 用 LangGraph 服务器运行、推送和保存运行

## 背景

[0007](0007-langchain-minimal-core.md) 让每个方法成为一张 LangGraph 图，但运行外壳仍是自建的：`Service` 启动后台任务，`RunLog` 把事件追加到 `events.jsonl`，页面按序号轮询，服务重启后未结束的运行只能标为中断。这一层与 LangGraph 服务器已有的线程、后台运行、可重放的流和检查点重复。

LangGraph 服务器（`langgraph-api`）有两种运行时。生产版自托管需要 LangSmith 企业许可证；内存运行时（`langgraph dev` 使用的 `langgraph-runtime-inmem`）不需要许可证，并把线程、运行和检查点保存到工作目录下的 `.langgraph_api/`。Rural-Agent 已用内存运行时在生产环境运行。

## 决定

- `llm4om serve` 以内存运行时启动 LangGraph 服务器。每个方法注册为一张平台图：`prepare → model → solve`。`langgraph.json` 注册同样的图，供 `langgraph dev` 和 Studio 使用。
- 运行是线程。前端用 `@langchain/langgraph-sdk` 创建线程和后台运行，并用可重放的流（`streamResumable`）显示过程。刚创建和稍后打开的运行走同一条路径：从第一个事件重放。
- 步骤作为 custom 流事件实时推送；节点结束时写入线程状态。实时能看到的步骤，运行结束后从状态中也能看到。LLM 正在写出的文本只实时推送，不写入状态；调用结束后，完整输出写入该步骤。
- 运行上下文只写代码写法、服务商名、模型名和方法参数。密钥留在本机设置文件中，由服务器读取。
- 平台自己的接口（选项、设置、模型列表、题库）和前端页面作为服务器的自定义路由挂载。
- 方法图在 `model` 节点内运行，不保存它的内部检查点。
- 删除 `Service`、`RunLog`、`Workspace`、`/api/runs` 和轮询。

## 取舍

- 前端不使用 SDK 的 `useStream`。它围绕对话消息设计，而运行页面展示的是步骤、数学模型、代码和求解结果；一个直接调用 SDK 客户端的小 hook 更简单。
- 停止运行会取消 `model` 节点，已推送的步骤不写入状态。再次打开时只能看到问题和“已停止”。
- 方法内部没有检查点，因此不能从方法中间恢复或分叉。将来需要“固定数学模型、只换代码写法”的分叉时，需要方法暴露明确的建模结束点。
- 内存运行时适合单机使用。多人或多机部署需要换用其他运行时，届时重新评估许可证。
- 旧版 `runs/<id>/` 目录中的运行记录不再显示在工作台中。
