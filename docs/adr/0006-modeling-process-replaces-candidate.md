# 以建模过程与阶段产物取代候选

“候选”把三件事绑在一起：Formulation／Code 的一次输出、平台的公开检查、方法的修正与选择。结果是重试被提升为与两阶段并列的概念。只改代码也复制整个包，修正链还被当作 Pass@k 独立样本。决定删除候选概念：表述阶段与代码阶段各自保存阶段产物及其父产物和改动理由；公开检查与最终选择是建模过程中的建模步骤；Pass@k 只在独立运行之间统计。

## 影响

- 平台检查仍是信任边界：最终选择只能指向已由平台实际编译、执行和求解的阶段产物组合，检查次数照常计入预算。
- 同一步骤可输出多个兄弟阶段产物（例如采样多个表述再投票），无需额外概念；多个建模方法并行解同一问题是多个运行，由界面切换。
- 已保存的 `candidates/` 运行通过只读适配器展示，不重写旧运行。
