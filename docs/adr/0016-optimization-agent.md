# 新增独立优化 Agent 入口，调用完整建模工作流

优化对话独立注册为 `optimization` 图。它从空白问题开始，提供多轮需求沟通、搜索、首次建模、实际结果查询和条件调整。原有 `requirements`、`solution_chat` 图及其历史继续可用；原工作台仍位于首页，“新建建模”及原有交互不变；新增侧栏“优化对话”入口与 `/agent` 页面，两套界面并列使用。原运行与对比链接保持有效。本决定扩展 0014 和 0015 的入口，不改变研究方法内部机制。

十三种方法通过一个 `model_and_solve` 工具调用。工具接收完整题面、方法、建模库与后端，附件从当前会话读取；未指定时使用 Direct、Pyomo 和自动后端。Agent 可通过 `modeling_capabilities` 查询原有方法注册表、问题范围及实际沙箱后端目录。固定的方法或建模库优先于模型填入的参数。明确改变条件时继续使用 `solve_scenarios`，继承固定基准的配置和数据。每轮只执行一个计算工具；多个业务场景交给同一个批量工具。

计算沿用 0015 的进程内平台图，不在同一运行队列中等待子 Run，因此单执行槽也能完成。工具把实际步骤推送到独立 custom 流，方法的消息流仍与 Agent 回复分开。完整结果以原生线程和检查点独立保存，对话保存引用。单个方案成为当前方案，多个业务场景保持共同基准；最终回复失败时，重试读取已保存结果。首次建模未保存完成时，重试使用原消息对应的完整请求和附件。

桌面界面以对话为主，计算过程中可展开任务步骤，数学模型、代码和完整结果在旁边的建模工作区查看。首次 Run 在导航前启动，进入或刷新对话时用 SDK `runs.list` 找到活动 Run，再用 `useStream.joinStream` 重连；不依赖启动页面的内存或私有 SDK 存储键。原运行页继续提供导出、对比和手动修改入口。删除对话不删除已独立保存的计算方案。

暂不增加通用图表推断、业务要求自动映射、任意代码执行工具或新的任务队列。平台继续由现有沙箱执行方法生成的代码。
