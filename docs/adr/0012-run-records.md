# 固定运行配置，用原生 Store 保留中断进度

方法图的 `model` 节点可能运行数小时。只在节点结束时记录状态，会在取消后失去已完成的工作；保存所有内部检查点又会反复复制 AutoFormulation 的搜索树。因此沿用平台检查点，并用 [LangGraph Store](https://docs.langchain.com/oss/python/langgraph/persistence#memory-store) 保存可展示的步骤和产物：运行时合并写入，取消时刷新，正常完成后由最终状态接管。

运行记录同时保存不含密钥的配置和独立执行时间。预设在建模节点开始时解析一次，后续角色共享它；密钥只存在于运行时对象中。历史记录无需依赖仍然存在的预设，修改备注也不会改变对比耗时。

新增预设使用随机 UUID，已有 ID 不变。这更新了 [0010](0010-llm-presets.md) 的名称生成规则：删除后重新添加同名模型也属于另一个预设，旧记录不能无意间选择它。方法通过 `Method.parameters()` 声明快照内容，平台不依赖内置参数变量的命名。

临时进度的生命周期由服务端统一管理。原生单个和批量线程删除入口先停止写入者，再删除线程和进度；客户端只发出删除线程请求。清理失败可以重试，线程已不存在时仍可清理孤立进度。这保留原生线程接口，也让命令行 SDK 与工作台具有相同的删除行为。

这更新了 [0009](0009-langgraph-server.md) 对中断记录的取舍。保存公开进度不提供从方法内部恢复执行的能力，也不新建数据库或事件日志；持久化周期仍由现有服务器运行时决定。
