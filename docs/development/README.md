## 30 天轮换开发任务

三位同学依次接手，每人 10 天，按课余零碎开发、大模型辅助安排，不按全职工时承诺。三人各有两条主要任务，并在当期完成涉及的 CLI、Web、配置与测试。完整平台责任不等于每人重新调查或重写整个仓库。

开始前，三人共同阅读三份任务书，并用同一个问题走通 CLI 与 Web，理解 30 天的整体目标和共同验收口径。每次交接由接手者复跑，不能只阅读上一位的完成报告。

按[贡献指南](../../CONTRIBUTING.md)复用现有本机开发环境。开工前确认仓库权限、Docker Worker 和测试 LLM 配置可用，密钥私下提供，不额外承担公网部署或跨平台环境适配。

| 执行人 | 周期 | 两条主要任务 | 交付版本与任务书 |
|---|---|---|---|
| 同学 A | 第 1—10 天 | 既有方法及必要抽象复核修正；第一个新求解器 | [七种方法、四个求解器的可运行基线](assignments/01-baseline-and-method-audit.md) |
| 同学 B | 第 11—20 天 | 主流程前端优化；LLMOPT 接入 | [八种方法、四个求解器的完整工作台](assignments/02-workbench-and-first-extension.md) |
| 同学 C | 第 21—30 天 | 第二种新方法；第二个新求解器，复用已有测试完成最终验收 | [九种方法、五个求解器的交付版本](assignments/03-platform-and-second-extension.md) |

## 范围与工作量

A 用第一个新求解器检验抽象，将复核与实际接入放在一起；B 集中完成前端与 LLMOPT；C 聚焦第二组新增项，复用前期成果完成最终回归。按工作性质减少切换与重复，不按代码量或固定工时追求机械均分。

逐方法复核贯通输入、数据、编排、提示、阶段产物、反馈、求解、最终选择及页面展示。A 深入复核七种既有方法，B 检查界面变化并完整复核 LLMOPT，C 完整复核第二种方法并检查全部记录及受影响环节。复核表和用例持续更新，不从头重复。

共用问题从已有测试和 fixture 中选择，可由同一问题覆盖多个数学条件，只补遗漏的案例。组合矩阵按 28 → 32 → 45 扩展；最终执行完整矩阵，不要求每个组合再运行全部问题、异常场景和真实 LLM。矩阵验证兼容，不能代替人工数学核对和真实步骤展示。

抽象只针对实际问题修正；前端优化聚焦问题输入、建模过程及成果阅读。整体布局和必要的视觉、可读性改进仍是 B 的必交付。复用现有 Gateway、执行器、插件和测试，不引入新的前端框架、插件体系、部署适配或报告系统。非关键视觉细节、非必要整理和未测出问题的性能专项排在修复、验证与交接之后。每期收尾保留处理回归的余量。

## 依赖与交接

| 交接 | 上一位必须交付 | 接手者先复跑什么 |
|---|---|---|
| A → B | 可运行的七方法四求解器版本；配置、步骤、产物引用和结果约定；新增求解器配置；方法复核表和共同用例 | CLI 与 Web 的正常求解、一个相关异常或澄清、产物与最终结果对应关系；确认新求解器可选且能真实求解 |
| B → C | 可运行的新界面与 LLMOPT；前端源码及构建文件；更新的同一份复核表、共同测试和必要接口变化 | 用新界面完成输入到结果，读取过程和版本；用 CLI 运行 LLMOPT；确认四个求解器的配置入口仍可用 |
| C → 最终验收 | 九方法五求解器版本；更新后的复核表；完整回归结果；可复用配置及启动说明 | 按 README 启动，用 CLI 与 Web 使用新增项，检查实际过程、产物、最终结果与导出 |

每次交接只需提交与现有资料链接，加一页以内的说明，写清运行命令、关键配置、接口变化、验证结果和已知问题。不要另建一套报告；运行示例通过测试或运行 ID 引用，密钥及私有运行材料不进入 Git。

谁改动接口，谁在同次变更中同步调用方、前端、配置、文档与测试，不把接通工作留给下一位。下一位先复跑关键用例，再开发新增内容。已通过且未受影响的数学复核可保留；当前行为仍需测试，提示或语义变化时补真实 LLM 与人工检查。

无法启动、可复现的工程计算错误或结果错配、关键产物或步骤缺失、双入口断开属于交接阻断项，上一阶段须修复。真实 LLM 的推理失败保留并单独归因，不能隐藏，也不等同于工程实现必然错误。非关键排版和美化细节可列为后续项。阻断项无法当期解决时，提前说明复现和影响，显式调整交接安排，不能标为已通过或默默挤占下一位任务。具体 bug 和状态沿用 GitHub Issues 跟踪。

新增总量保持两种方法和两个求解器。只固定 LLMOPT，其余由对应执行人选择；后续选型先看前期清单，避免重复。优先选择可复用当前接口、无需训练或另建执行环境的方案。
