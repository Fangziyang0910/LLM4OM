# 任务书三 第二组方法求解器接入与平台整体验收

执行人：同学 C。周期：第 21—30 天。起点：同学 B 已验收并合入的 `main`。

## 交付目标

在 B 交付的八种方法、四个求解器基线上，完整接入第二种新建模方法和第二个新求解器。复用前两阶段的方法复核及测试，补齐新增项和受影响部分，完成整体回归，交付九种方法、五个求解器可从 CLI 与 Web 使用的平台。

按课余开发和大模型辅助安排。两条开发任务是一个新方法和一个新求解器，最终验收复用已有用例和复核表，不从头重做全仓调查或前端设计。你负责新增项与改动涉及的前后端适配。当前范围仍是本机单用户、LP/MILP 和通用外部 LLM。

## 具体任务

1. **复跑并核对交接基线。** 先复跑约定的 CLI、Web 关键用例，确认 A、B 的复核记录和测试可用。后续通过既有回归检查原有八种方法，只对失败、缺失证据或被本阶段改动影响的环节补查源码。
2. **完整接入第二种新建模方法。** 在本阶段前段给出名称、论文或源码入口、核心思路和选型理由。要求与已有方法不重复，可从自然语言与可选业务数据开始，不依赖专用训练权重。选择能复用当前接口的提示流程，实现核心编排，记录固定来源与适配差异，并贯通 CLI、Web、产物和导出。
3. **完整接入第二个新求解器。** 在本阶段前段确认官方资料、支持范围、依赖、许可及选型理由，与 A 接入的求解器及既有实现不重复。复用共同执行路径，补齐真实安装、声明、预检、配置、结果处理及双入口，不增加新的执行体系。
4. **完成九种方法复核记录。** 沿用 A、B 已完成的输入、数据、编排、提示、Formulation、Code、反馈、求解和展示检查。对第二种新方法完整检查同样环节，补查受影响的既有方法。现有记录不等于当前行为已通过；用回归测试验证未退化，有语义或提示变化时再补人工及真实 LLM 检查。
5. **完善可展示的完整成果。** 为九种方法逐一确认页面能查看真实步骤、阶段产物、修正和最终模型、代码、结果。处理布局、状态和阅读上的剩余问题，防止新增阶段或错误类型被页面遗漏。最终结果、历史版本和导出保持同源。
6. **完成整体回归和交付。** 沿用现有脚本运行共同问题、组合测试及完整回归，修复新增或被影响的功能问题。核对 README 的启动命令和支持范围，在干净的一次性工作区完成启动验收。只处理已复现的明显性能问题，不新增基准系统或重做已有界面。

## 必要指引

先读[任务书一](01-baseline-and-method-audit.md)、[任务书二](02-workbench-and-first-extension.md)及交接材料，复用共用问题和逐方法复核表。方法与数值执行的接口见[方法契约](../../contracts/methods.md)和[执行契约](../../contracts/execution.md)，检查入口见[测试指南](../testing.md)。

接口变化仍由本阶段负责同步全部调用方、配置、前端和测试。共同 Pyomo 路径承担组合验证；gurobipy 原生路径保留其实际支持限制，不能为扩大矩阵而伪称可切换到其他求解器。

B 必须交付可用的 LLMOPT、四个求解器、新界面和共同测试，C 不承担前两阶段尚未接通的功能。具体输入和阻断项处理见[共同安排](../README.md#依赖与交接)。

## 完成验收

- 第二种方法在至少 2 个不同的小问题上使用真实 LLM 验证，覆盖 CLI 和 Web，并人工核对各阶段与最终解；异常或修正分支用确定性回复检查。第二个求解器完成真实安装、预检、构建和求解，来源、配置及使用条件清楚。
- 九种方法都有更新后的全链路复核记录与页面演示。每个实际环节有对应证据，未提供的阶段与尚未验证的语义如实说明；发现的工程偏差已修复并有相应回归。
- 复用 B 的 32 个组合，补上第二种方法与四个求解器的 4 个组合，以及第二个新求解器与九种方法的 9 个组合，共同 Pyomo 路径达到 45 个组合。用确定性回复和真实求解器执行完整矩阵，既有原生路径按实际支持组合回归。
- 共用问题覆盖五个求解器的声明能力。可行解满足独立预期的域、约束及目标容差，多解不要求相同向量；无解、无界、时间限制及失败有对应检查。复用现有数值测试和 A 的用例，只补缺失部分，不要求所有方法与所有求解器再交叉运行全部异常用例。
- CLI 与 Web 均能配置并使用全部新增项，确定性输入与配置的结果及状态一致。完整 Python 回归、类型检查、前端构建、核心浏览器流程和文档检查通过。真实 LLM 与确定性回放的结果分别记录。
- 从 README 可启动后端与 Web，完整完成问题输入、配置、建模过程查看、结果阅读、历史及人工修改。最终更改集成到 `main`，本地与远端一致，工作区干净。
