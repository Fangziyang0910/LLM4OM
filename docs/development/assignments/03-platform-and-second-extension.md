# 任务书三 第二组方法求解器接入与平台整体验收

执行人：同学 C。周期：第 21—30 天。起点：同学 B 已验收并合入的 `main`。

## 交付目标

完整接入第二种新建模方法和第二个新求解器。继续修复抽象、前端和主流程中的实际问题，全面复核九种方法的编排、各阶段实现、可展示过程与成果，交付九种方法、五个求解器可从 CLI 与 Web 使用的平台。

你负责最后一个完整版本，并复核前两阶段成果。新增插件、整体检查和界面完善均需贯通前后端。当前范围仍是本机单用户、LP/MILP 和通用外部 LLM，不扩展公网部署、多平台或训练任务。

## 具体任务

1. **复跑并核对交接基线。** 使用共同问题从 CLI 和 Web 复查现有八种方法与四个求解器，核对步骤、产物、选择与展示。定位并修复遗留偏差，不能只检查即将新增的内容。
2. **完整接入第二种新建模方法。** 第 22 天结束前给出名称、论文或源码入口、核心思路和选型理由。要求与已有方法不重复，可从自然语言与可选业务数据开始，不依赖专用训练权重。实现可识别的核心编排及阶段提示，记录固定来源与适配差异，并贯通 CLI、Web、产物和导出。
3. **完整接入第二个新求解器。** 第 22 天结束前给出官方资料、支持范围、依赖、许可及选型理由。与此前求解器不重复，复用共同执行路径并完成真实安装和验证。补齐声明、预检、Worker、配置、页面选项及标准化结果，不只更换名称或包装。
4. **复核九种方法的每个环节。** 逐方法检查输入及数据、提示与编排、Formulation、Code、错误反馈、修正、最终选择和真实求解。对照问题和独立预期检查数学含义；将代码可运行、当前模型最优和原问题建模正确分别判断。修复发现的实现偏差，更新逐方法复核表。
5. **完善可展示的完整成果。** 为九种方法逐一确认页面能查看真实步骤、阶段产物、修正和最终模型、代码、结果。处理布局、状态和阅读上的剩余问题，防止新增阶段或错误类型被页面遗漏。最终结果、历史版本和导出保持同源。
6. **完成整体优化和交付。** 基于实际测量处理明显卡顿、重复请求或不必要包装。运行共用问题、组合测试及完整回归，修复影响使用的 bug。核对 README 的启动命令、支持范围及使用步骤，用干净的一次性工作区完成启动和操作验收。

## 必要指引

先读[任务书一](01-baseline-and-method-audit.md)、[任务书二](02-workbench-and-first-extension.md)及交接材料，复用共用问题和逐方法复核表。方法与数值执行的接口见[方法契约](../../contracts/methods.md)和[执行契约](../../contracts/execution.md)，检查入口见[测试指南](../testing.md)。

接口变化仍由本阶段负责同步全部调用方、配置、前端和测试。共同 Pyomo 路径承担组合验证；gurobipy 原生路径保留其实际支持限制，不能为扩大矩阵而伪称可切换到其他求解器。

## 完成验收

- 第二种方法在至少 3 个不同的小问题上使用真实 LLM 验证，覆盖 CLI 和 Web，并人工核对各阶段与最终解。第二个求解器完成真实安装、预检、构建和求解，来源、配置及使用条件清楚。
- 九种方法都有更新后的全链路复核记录与页面演示。每个实际环节有对应证据，未提供的阶段与尚未验证的语义如实说明；发现的工程偏差已修复并有相应回归。
- 九种方法与五个求解器在共同 Pyomo 路径上的 45 个组合通过确定性回复加真实求解检查，既有原生路径按实际支持组合回归。该矩阵证明执行兼容，不能替代逐方法的数学含义和展示检查。
- 使用至少 12 个共用问题检查五个求解器。可行解满足独立预期的域、约束及目标容差；多解不要求相同向量。无解、无界、时间限制及求解失败有对应检查，未知数值不填造。
- CLI 与 Web 均能配置并使用全部新增项，确定性输入与配置的结果及状态一致。完整 Python 回归、类型检查、前端构建、核心浏览器流程和文档检查通过。真实 LLM 与确定性回放的结果分别记录。
- 从 README 可启动后端与 Web，完整完成问题输入、配置、建模过程查看、结果阅读、历史及人工修改。最终更改集成到 `main`，本地与远端一致，工作区干净。
