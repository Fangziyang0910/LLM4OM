# 任务书三 第二组扩展与平台整体验收

执行人：同学 C。周期：第 21—30 天。起点为 B 已验收并合入的 `main`。接口与共同验收以[共同安排](README.md)为准。

## 交付目标

在 B 的九种方法基线上，完整接入第二种新方法和第二个新增求解器。复用前两阶段的检查，交付十种方法及新增后的六个求解器绑定；兼容范围以实际声明和验证为准。

## 具体任务

1. 阅读[任务书一](01-baseline-and-method-audit.md)、[任务书二](02-workbench-and-first-extension.md)及交接结果。先复跑 CLI 与 Web、配置、取消、历史和结果对应关系。原有方法通过既有回归检查，仅补查失败或被本阶段影响的环节。
2. 选择与已有方法不同的新建模方法，记录论文、固定源码版本、核心流程及适配差异。选择可以使用通用外部 LLM、问题描述和可选数据的方法，不增加专用训练任务。实现真实编排并接通 CLI、服务端注册、Web、过程和下载，具体步骤见 [CONTRIBUTING](../../../CONTRIBUTING.md#接入研究方法)。
3. 选择与 A 及原有四个求解器不同的第二个新增求解器。记录官方来源、依赖、许可和能力，在现有语言及 Worker 路径完成最小扩展，同步提示、声明、依赖、配置、CLI、Web 和测试，不增加新的执行体系。
4. 为新方法完整核对输入、数据、提示、数学模型、代码、反馈、修正和选择规则。为新求解器补充全部声明支持的方法组合。保留 CP 与 MILP 的能力区分，不将所有方法与求解器的笛卡尔积当成已支持范围。
5. 在干净的一次性工作区按 README 启动，检查真实步骤、最终结果、历史和下载。复用 [方法验证](../../methods.md#验证) 与 `tests/`，仅补新增项和受影响用例；发现可复现的工程错误先修复，再做整体验收。

## 完成验收

- 第二种新方法至少在两个不同的小问题上使用真实 LLM 加真实求解，覆盖 CLI 与 Web，人工核对数学含义及解；确定性回复覆盖异常与修正。
- 第二个新增求解器真实安装并求解，来源和使用条件清楚。既有与新增声明组合通过回归，不支持组合明确拒绝。
- 十种方法的流程、适配和验证记录完整。可行解满足独立的变量域、约束和目标预期，多解不要求同一向量；不可行、无界、时间限制、失败和约束满足问题按声明能力检查。
- CLI 与 Web 能使用全部新增项。Ruff、Python 完整回归、前端 lint、前端测试和构建通过。方法支持范围、启动命令、依赖与来源文档更新。
- 按 README 从空工作区启动并操作成功，最终提交合入 `main`，本地与远端一致，工作区干净。真实 LLM 和确定性测试的结果分别记录，未解决项不能标为通过。

前段确定方法和求解器选型，中段实现并补证据，收尾执行完整回归并预留修复时间。最终提供 `main` 提交、共同验证记录和测试入口、新增项配置与来源，以及一页以内的启动和已知问题说明。密钥、运行数据和许可证留在 Git 忽略位置。
