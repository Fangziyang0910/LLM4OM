# 任务书一 前端重构与用户流程完善

执行人：同学 A。周期：第 1—10 天。起始基线：`main` 提交 `46c9d35`。

## 交付目标

交付一个布局清楚、视觉统一、操作顺畅的 Web 工作台。用户可以输入问题，选择模型、方法和求解器，开始建模，查看实际过程、数学模型、求解代码和结果。本阶段完成前端主线，为后续新增方法和求解器保留统一入口。

开发范围是本机单用户 Web。已有 CLI 保持可用。公网部署、多平台适配和模型训练不属于本次任务。

## 具体任务

1. **重新组织页面与视觉设计。** 围绕问题输入、建模过程和产物组织整体布局，统一排版、间距、对齐、按钮、表单和弹窗。允许重构现有布局；不能只更换配色。普通操作直接可见，预算、原始记录和高级配置按需展开。
2. **完善完整用户流程。** 复核供应商设置、密钥掩码、模型选择、方法与求解器选择、提交、澄清、失败提示、历史浏览和人工修改。处理切换配置后的状态同步，避免旧请求覆盖新选择。区分新建问题与返回已有草稿。
3. **准确展示过程与结果。** 只展示实际执行的步骤。最终数学模型、代码和结果必须属于同一选中版本。明确区分运行完成、模型最优、不可行和执行失败；缺少信息时不能补造。原始数据、诊断和中间产物放在对应入口。
4. **整理前端职责。** 梳理组件、类型、配置状态和产物读取。合并重复状态，减少按文件名猜测产物的逻辑。方法和求解器选项复用已有能力声明及预设，避免为后续每个新增项复制一套页面。
5. **补充交互测试并处理卡顿。** 复用现有浏览器测试，补上改动涉及的正常和异常流程。重点检查重复提交、迟到响应、版本切换和草稿保留。发现明显卡顿或重复请求时，先记录触发条件，再做针对性优化。

## 完成验收

- 在 1280 和 1440 像素宽的桌面窗口中，主要内容无横向溢出，表单、弹窗和产物区域布局完整。提供修改前后截图，展示整体布局与信息层次的变化。
- 完成正常求解、无效输入、模型服务失败、取消、澄清、历史版本及人工修改的演示。对应场景有可重复的浏览器检查。
- 刷新页面及重启同一工作区后，供应商设置和历史记录可恢复；密钥保持掩码展示，不进入公开记录。
- 页面展示与后台最终产物一致。切换方法、模型、求解器或运行版本后，不串用配置、结果和编辑模板。
- 前端类型检查、构建及受影响的浏览器测试通过。源码和随包构建文件同步提交；原有 CLI 示例仍能完成求解。
