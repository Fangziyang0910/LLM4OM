# 任务书一 现有方法复核与首个新增求解器

执行人：@chuleipangtong（同学 A），GitHub [#107](https://github.com/Fangziyang0910/LLM4OM/issues/107)。周期：第 1—10 天。记录开工时的 `main` 提交。接口与共同验收以[共同安排](README.md)为准。

## 交付目标

在 v0.40 的八种方法、四种语言和求解器绑定上，复核实际流程与数学含义，修复剩余问题，并完整接入第一个新增求解器。当前维护已完成一轮工程修复和前端整理；先复用现有证据，重点补真实 LLM 和独立数学核对。

## 具体任务

1. 对照 [方法说明](../../methods.md) 的固定来源和适配记录，逐一追踪八种方法的输入、编排、提示、数学模型、代码、反馈、修正和最终选择。没有的阶段如实说明，不能补造统一流程。
2. 用有手算或独立检查依据的问题核对变量域、目标方向、约束、常数和数据绑定。覆盖不同问题，包含能暴露漏整数域、漏约束或错数据的例子。工程实现错误与 LLM 推理错误分别记录。
3. 从 [graph.py](../../../src/llm4om/graph.py)、[runtime.py](../../../src/llm4om/runtime.py) 和 [RunView.tsx](../../../frontend/src/components/RunView.tsx) 追踪同一次运行。确认 CLI、实时步骤、最终结果、历史和下载内容一致，复核取消、超时和重新连接。
4. 选择与现有 HiGHS、Gurobi、SCIP、CP-SAT 不重复的求解器，记录官方来源、依赖、许可和支持范围。沿 [languages.py](../../../src/llm4om/languages.py) 与 [worker.py](../../../src/llm4om/sandbox/worker.py) 的现有绑定实现最小扩展，同步提示方言、方法支持声明、Worker 依赖、CLI、Web 和测试。不要恢复旧 SolverBackend，也不要假定 Pyomo 已支持任意切换求解器。
5. 更新 [方法验证](../../methods.md#验证) 及现有测试。复用已完成的回归，不重做旧版接口调查或建立新的测试框架。前端只修已确认的流程及显示问题，整体体验完善由 B 负责。

## 完成验收

- 八种方法都有预期流程、实际流程、适配差异和验证记录。每种方法至少一次真实 LLM 加真实求解，由人核对问题、数学模型、代码和解；既有有效证据可以复用。
- 新求解器真实安装并求解成功。声明支持的全部方法组合通过确定性回复和真实求解；不支持的组合在开始调用 LLM 前拒绝。CPMpy 的约束满足问题单独核对。
- 通过相关正常、不可行、无界、失败、取消及超时检查；不要求不支持的状态或组合。新增绑定能从 CLI 与 Web 选择并使用，结果与下载内容一致。
- Ruff、Python 回归、前端 lint、前端测试和构建通过。源码、随包构建文件、依赖和文档同步提交。
- 按[交接规则](README.md#依赖与交接)交付给 B。前段确认求解器选型，中段实现并复核，收尾预留修复与交接时间。阻断问题修复后才算完成。
