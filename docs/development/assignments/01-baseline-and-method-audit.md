# 任务书一 现有方法全链路复核与平台基线校正

执行人：同学 A。周期：第 1—10 天。起点：开工时的 `main`，记录实际提交。

## 交付目标

逐一检查现有七种方法，从问题输入一直追踪到页面展示，修正影响正确性和后续接入的问题。接入第一个新求解器，用具体扩展检验核心接口。交付七种方法、四个求解器均可从 CLI 与 Web 使用的平台基线。

30 天共同目标包括整体前端优化、抽象校正、两种新方法和两个新求解器。后续接入只固定 LLMOPT，其余选型开放。本阶段要使这些扩展能沿共同接口完成，不提前堆叠新框架。

按课余开发和大模型辅助安排。本阶段重点是已有方法复核、必要修正和一个求解器接入；前端只修流程和显示错误，整体视觉重构交给 B。修改涉及前端、后端、配置或测试时，由你同步完成。当前范围是本机单用户、LP/MILP 和通用外部 LLM。

## 具体任务

1. **按用户目标核对实现。** 完整操作 CLI 和 Web，梳理“输入问题与数据 → 选择配置 → 方法编排 → 数学表述 → 代码 → 检查与求解 → 最终选择 → 页面与导出”。用可观察结果判断是否实现正确，不能仅凭已有文档或通过的测试下结论。
2. **逐一复核七种方法。** 覆盖 Direct、Feedback Repair、OptiMUS、CoE、OptiTree、OR-LLM-Agent 和 AutoFormulation。对照用户确认的适配目标、方法核心思路和实际源码，核对编排、阶段提示、阶段输入与输出、数据使用、错误反馈、修正和选择规则。区分有意适配与实现错误，修复空转步骤、忽略反馈、只换名称等偏差。
3. **检查数学含义与执行的一致性。** 用有手算或独立检查依据的问题，核对目标方向、变量域、约束、常数和数据绑定。检查 Formulation、实际执行的 Code、求解模型与结果的对应关系。加入能区分漏约束、漏整数域或错数据绑定的反例，不能只重复验证目标值 13。
4. **校正必要的抽象和接口。** 核对问题、LLM、方法、Formulation、Code、建模后端、求解器及运行记录的职责。只修已复现的职责混用、重复处理和接入障碍，不承担全仓重写。沿用已有契约，说明配置、步骤、产物引用和结果的实际含义，供 B 直接使用。
5. **同步修复过程与产物展示。** 页面应展示各方法真实执行的步骤、阶段产物、检查、修正理由和最终输出。中间结果与最终结果、方法原始表述与提取视图区分清楚。阶段未提供时如实说明，不能补造统一流程。保证模型、代码和结果属于同一选中运行与版本。
6. **接入第一个新求解器。** 在本阶段前段完成选型，记录名称、官方资料、支持范围、依赖及许可。选用可在当前 LP/MILP 路径验证的新增实现，复用 SolverBackend、Worker 和 Pyomo 路径。补齐声明、依赖、预检、结果处理、CLI 配置与 Web 选项，不把实际接通工作交给 B。
7. **复用并补齐共同验收用例。** 从已有测试和 fixture 中选取有独立预期的小问题，覆盖 LP/MILP、目标方向、变量域、数据、常数、不可行和无界。优先复核 JSON 回复抽取、截断回复、不完整数据和缺信息等问题。只补缺失用例，不为数量另建测试集或测试框架。

## 必要指引

先读 [README](../../../README.md)、[领域术语](../../../GLOSSARY.md)、[方法说明](../methods.md)和[方法契约](../../contracts/methods.md)。从 [application.py](../../../src/llm4om/application.py)、[methods.py](../../../src/llm4om/methods.py) 和 [RunView.tsx](../../../frontend/src/components/RunView.tsx) 追踪同一次运行。

Formulation 表达数学含义，Code 保存计算实现，求解器执行数值优化。严格 IR 是一种表示路径，不应为统一接口而强迫所有方法使用同一种编排。需要澄清或没有某阶段的情况，按方法实际支持能力处理。

复核表只维护一份，使用现有测试、运行 ID 和产物引用提供证据。具体依赖及交接规则见[共同安排](../README.md#依赖与交接)。

## 完成验收

- 提供逐方法复核表。七种方法均记录预期流程、实际流程、各阶段输入输出、发现偏差、修正和验证证据。每种方法均检查到 CLI、Web 过程展示及最终产物，不能只检查方法函数。
- 每种方法有正常流程，以及与其声明能力相关的异常或修正检查；至少有 1 次真实 LLM 加真实求解的运行，由人核对问题、数学表述、代码和解。不同方法可复用共同问题，模型推理错误与工程实现错误分别记录。
- 第一个新求解器完成真实安装、预检、构建及求解。复用现有 21 个组合检查，补上新求解器的 7 个组合，共同 Pyomo 路径达到 28 个组合；既有原生路径按实际支持组合回归。组合测试不代替数学含义与展示的检查。
- 选定问题的步骤和产物可在 Web 完整查看，能追到真实调用、修正和最终选择。无解、执行失败和成功求解均展示正确状态；CLI 与 Web 使用相同配置语义。
- 共同验收问题、逐方法复核表、求解器配置和必要接口说明可由 B 直接复用。已确认的阻断问题已修复，类型检查、前端构建和受影响测试通过。
