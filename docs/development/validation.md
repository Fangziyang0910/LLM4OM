# 支持验证

本文保留判断当前支持范围所需的证据。它不承担逐次开发日志；新的检查结果随提交或工作项记录。这里的历史成功不保证外部服务持续可用。

## 方法与求解器

2026-10-16，基于提交 `90a907d` 的实现重新验证七种方法与 HiGHS、Gurobi、OR-Tools 的全部 21 个组合。确定性 HTTP 回复驱动实际方法流程，真实容器求解均得到手算目标 13。2026-10-15 的 Web 验收还覆盖了页面生成的 21 个配置及对应真实预检。

这组证据证明工程兼容性。它没有调用付费 LLM，也不代表全量建模准确率。复查命令见[测试指南](testing.md)。

2026-10-16，Direct、Feedback Repair 和四个研究提示流程的 gurobipy/Gurobi 工厂组合均通过真实容器求解。Feedback Repair 的验证还覆盖执行失败后的代码修正和原表述引用保留。Gurobi 验证限实际有限规模环境。

## 调度与故障基线

较早 SDK 0.28.0 的本机参考环境限制为 4 个逻辑 CPU、8 GiB、并发 4。1000 个离线任务全部保存；直接执行参考中位数 2.678 秒，调度附加耗时 P95 为 0.209 秒，整批含预检/报告为 706.472 秒。该测量不含真实 LLM 或求解器，不代表当前快照的重新测量。

同一阶段的 100 个 CLI 故障任务包含正常、非法 JSON、429、超时和取消各 20 个，保留 100 个唯一运行。复查入口为 `scripts/acceptance_load.py` 和 `scripts/acceptance_faults.py`。CLI 故障集合与实验调度恢复分别提供证据。

## 模型目录与题库

供应商目录协议通过本机 HTTP 测试覆盖全部预设。2026-10-15，DeepSeek 真实目录和 OpenRouter 匿名目录已读取成功；其他供应商未逐家用真实密钥验收。GLM 标准目录与百炼既有地址仍需实际账户确认。

内置 2033 条题面已逐条与 OPT-Agent 管理器输出核对 ID、顺序和描述，并检查重新生成的哈希。浏览、复制和带入建模有 HTTP 与浏览器验证。这不代表题库全量求解或准确率验证。

## 环境边界

完整隔离验证使用 Linux Docker。macOS/Windows 未完成同等验证。公开多用户部署和正式 1.0 发布不属于当前本机交付范围。

旧布局运行保留只读展示；严格恢复要求原 SDK、插件、配置、数据与 Worker 身份一致。服务代码更新后需重启进程，避免旧模板与新校验混用。旧失败记录保留原状，不事后改成成功。
