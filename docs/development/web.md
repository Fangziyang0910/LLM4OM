# Web 工作台开发

用户操作见 [README](../../README.md)。本文说明页面职责、构建和 HTTP 边界。字段见 [Web 契约](../contracts/web.md)。

## 页面结构

首页围绕问题输入组织。模型、求解器和开始按钮位于输入区底部，方法和预算位于“建模选项”。顶部提供新建问题、示例题库和历史记录。

提交后进入任务工作区，默认展示结果。“数学模型”和“求解代码”切换阶段产物；过程面板展示真实步骤、公开检查和最终选择。需要澄清时展开回答入口。历史修正来自对应运行引用，不从其他产物推测补齐。

模型、选项、历史和人工修订使用共享 `Dialog`。对话框支持键盘、Escape、焦点恢复和有界滚动。窄屏在过程与产物间切换，交互动画尊重减少动态效果的系统设置。

| 位置 | 职责 |
|---|---|
| `frontend/src/App.tsx` | 启动配置、导航和页面组合 |
| `useRunSnapshot.ts` | 运行/版本选择、轮询和过期响应过滤 |
| `components/ProblemEditor.tsx` | 问题、附件、有效配置和预检 |
| `components/RunView.tsx` | 结果、阶段产物、版本与编辑入口 |
| `components/StoryFlow.tsx` | 建模步骤、公开检查和最终选择 |
| `components/RevisionEditor.tsx` | 模板、编辑草稿和派生提交 |
| `components/Dialog.tsx` | 共享原生对话框行为 |

表中的源码位置用于定位。接口字段在契约维护，组件和类型以当前源码为准。

## 构建与服务

```bash
npm --prefix frontend install
npm --prefix frontend run build
```

构建先检查 TypeScript，再生成固定的 `index.html`、`app.js` 和 `style.css`。文件输出到 `src/llm4om/web_assets/` 并随 Python 包分发。修改前端后提交对应构建文件。

Web 后台通过独立 CLI 应用进程调用共同用例。预检、插件发现和运行不共享同一解释器。更新后端代码后必须重启长驻服务，再刷新页面，避免旧模板与新执行程序混用。

## 数据与权限

服务默认监听 `127.0.0.1`。现有同源、Host 和进程令牌检查用于保护本地请求。`--host 0.0.0.0` 只适用于可信网络；当前工具没有多用户认证设计。

上传单文件上限为 8 MiB，JSON 请求上限为 24 MiB，公开导出上限为 64 MiB。默认最多同时运行 2 个任务，活动和排队任务合计最多 8 个。

公开产物读取核对命名空间、相对路径、大小和哈希。导出按已保存公开引用收集，不遍历私有资源目录。页面仅呈现服务返回的公开内容。

上传预览只返回有界表格，不保存运行或发起生成。CSV/JSON 最多展示 20 行或字段、16 列、每格 256 字符。显示截断与模型实际数据视图的完整性分别标明。

## 交互约束

- 表单只维护一份有效配置。高级 JSON 草稿显式应用后生效。
- 模型目录只在编辑器可见时自动读取；直接打开结果不触发生成或目录 POST。
- 版本切换使旧模板响应失效；迟到响应不覆盖当前选择。
- 模型修改创建派生运行，保存父记录和累计预算。
- 目标值、解、状态和阶段产物来自最终选择；中间解只出现在对应检查中。
- 旧 `candidates/` 布局仅做只读展示，不迁移或改写历史文件。

浏览器检查方法见[测试指南](testing.md)。
