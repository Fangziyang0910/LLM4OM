## NLP4LP: actual schema and variation

The only declared split is `train.jsonl`: 361 records, original `id` strings `1`–`361`; difficulty `type` values easy 289, hard 65, case study 7. These are not train/dev/test partitions. Every record has exactly `id`, `type`, `description`, `parameters`, `optimus_code`, `problem_info`, `solution`, `keywords`, `parametrized_description`. `description`, `parameters`, `optimus_code`, `id`, `type` are strings in all 361. **Nested parameters/problem_info/solution are JSON serialized inside strings**, not ordinary outer JSON objects. `problem_info` and `parametrized_description` are strings in 355 and null in 6; `keywords` is list in 355 and null in 6. `solution` is string in 324 and null in 37. [Actual train file](https://huggingface.co/datasets/udell-lab/NLP4LP/blob/f0f2abb5d4fa01812ab2c818dd350f6c34041d15/train.jsonl).

Missing problem_info IDs: 28, 51, 57, 123, 126, 135. Missing solution IDs: 28, 57, 58, 68, 77, 79, 83, 103, 123, 126, 135, 171, 179, 181, 184, 219, 224, 237, 238, 240, 244, 251, 261, 266, 267, 276, 277, 297, 311, 312, 315, 317, 326, 358, 359, 360, 361. [Fixed release tree](https://huggingface.co/datasets/udell-lab/NLP4LP/tree/f0f2abb5d4fa01812ab2c818dd350f6c34041d15/data).

All parameter files parse as objects keyed by instance-specific parameter names. Across top-level parameter values: int 1,829, list 451, float 152, dict 26, string 2. The strings are ID 317's `K="5"` and `NumIndustries="3"`. Preserve them rather than silently coercing every parameter to scalar floats. Arrays and keyed dictionaries need shape/index binding. metadata.json contains only `type`. All 355 problem_info files share `parametrized_description` (str), `keywords` (list), `parameters` (dict), `variables` (dict), `constraints` (list), `objective` (dict). Representative parameter declarations have `description`, `shape`; variable declarations `description`, `type`, `shape`; constraint declarations `description`, `formulation`, `code`; objective has the same three fields. This is richer reference formulation material, not public raw input. [Representative parameter file](https://huggingface.co/datasets/udell-lab/NLP4LP/blob/f0f2abb5d4fa01812ab2c818dd350f6c34041d15/data/1/parameters.json), [problem_info](https://huggingface.co/datasets/udell-lab/NLP4LP/blob/f0f2abb5d4fa01812ab2c818dd350f6c34041d15/data/1/problem_info.json).

There is no uniform flat-vector contract. No solve status/certificate is supplied by these two solution fields. [Malformed ID 3](https://huggingface.co/datasets/udell-lab/NLP4LP/blob/f0f2abb5d4fa01812ab2c818dd350f6c34041d15/data/3/solution.json), [malformed ID 51](https://huggingface.co/datasets/udell-lab/NLP4LP/blob/f0f2abb5d4fa01812ab2c818dd350f6c34041d15/data/51/solution.json).

There are no additional CSV/XLSX/DAT paths in this release tree and no such filename markers in descriptions; concrete parameters are the external data files actually supplied. This screen is not a complete nonlinearity classification, and difficulty labels are not domain labels. ## MAMO: actual schema and evaluation

Canonical EasyLP has 652 records; ComplexLP 211; ODE 346. All have exactly `id` (int), `Question`, `Answer`, `Category`, `Type` (all strings). IDs are unique within each file but restart at 1; preserve subset and ID together. Optimization Category is `optimization`; Type is respectively `easy_lp`/`complex_lp`. ODE Category is `ordinary_differential_equation`; types first_order_equation 196, second_order_equation 110, system_equation 40. **Exclude all 346 ODE records even though all their Answer strings also parse numerically.** [EasyLP](https://github.com/FreedomIntelligence/Mamo/blob/2c91069dee5c1e4db4b899eb176ec987d0251bb3/data/optimization/Easy_LP/mamo_easy_lp.jsonl), [ComplexLP](https://github.com/FreedomIntelligence/Mamo/blob/2c91069dee5c1e4db4b899eb176ec987d0251bb3/data/optimization/Complex_LP/mamo_complex_lp.jsonl), [ODE](https://github.com/FreedomIntelligence/Mamo/blob/2c91069dee5c1e4db4b899eb176ec987d0251bb3/data/ode/mamo_ode.jsonl).

All 863 optimization Answer strings parse as finite floats. Public input is Question with original subset/ID and provenance; Answer stays private. There are no per-record model, reference code, vector, domain, solve status or external data-path fields. Canonical data directories contain only those three JSONL files; few-shot select_data files are derived examples, not extra benchmark splits. No extra parameter files are prescribed by README. Questions can contain inline LaTeX/data; do not discard these. [MAMO data instructions](https://github.com/FreedomIntelligence/Mamo/blob/2c91069dee5c1e4db4b899eb176ec987d0251bb3/README.md).

An explicit text screen (`integer|whole number|binary`, case-insensitive) matches EasyLP 632/652 and ComplexLP 3/211; `round` matches 577/652 and 29/211. These are wording counts, not inferred domain classifications. No `quadratic|non.?linear|squared|square of` or differential marker was found in optimization Question fields; this does not certify linearity. Review integer/continuous domains and whether Answer is a rounded requested answer before comparing it to an unrounded solver objective. [Canonical question files above](https://github.com/FreedomIntelligence/Mamo/tree/2c91069dee5c1e4db4b899eb176ec987d0251bb3/data/optimization).

The author optimization scorer reads generated .lp through COPT, takes model.objval, and compares with Answer. Its decimal-aware check accepts absolute error below 10^-max(2, decimal digits) OR relative error ≤1e-4. For zero reference its helper computes `difference * 1e-4`, producing a broad acceptance condition. Its denominator is the number of generated .lp files, not a frozen selected-question count. These are author implementation observations; they should not silently become the platform protocol. [Author scorer](https://github.com/FreedomIntelligence/Mamo/blob/2c91069dee5c1e4db4b899eb176ec987d0251bb3/scripts/scripts_optimization/mamo_script_optimization/3.run_code_comp_optimization.py).

## Minimum implementation implications; import versus evaluation

1. Use the existing public/private snapshot contract. Preserve original bytes, IDs, subset/difficulty, source commit, file and raw-record hashes, projection revision, domain policy, eligibility and exclusion reason. Never mount full train.jsonl or source directories into method execution: these contain oracle fields.
2. NLP4LP can supply 361 public descriptions with concrete parameters; missing/invalid private material must not remove an otherwise importable public question. Decode nested JSON strictly and retain malformed-reference diagnostics. Cross-check aggregate versus per-instance bytes before choosing one canonical representation; this research did not establish their semantic equivalence.
3. NLP4LP's 322 valid objective/vector objects are **potential supplied-reference objective comparisons**, not independently verified optima or feasibility certificates. Actual LP/MILP eligibility and decision-variable mapping remain to be reviewed; exclude nonlinear structures, ODE and unresolved parameter/domain bindings. Missing 37 and malformed 2 are explicit reference exclusions.
4. MAMO's 863 optimization records are import candidates and numeric-answer comparison candidates. Final objective eligibility depends on LP/MILP/domain/rounding review. With no reference model/vector, independent feasibility and full formulation correctness remain `not_available`. The author COPT dependency does not establish platform solver support.
5. Freeze selected and eligible counts before runs; retain generation, execution and checker failures. Do not implement the author's generated-file denominator or zero-answer tolerance without an explicitly named fidelity protocol.

No implementation, tests/CI, solver execution, paid LLM calls, other agents, remote issue/PR changes, commits or branch changes occurred. Only this note was written in the project; temporary evidence stayed in the authorized directory. Remaining work is per-record mathematical/domain/rounding review, aggregate/directory consistency, provenance checks for upstream source problems, and real evaluator acceptance; no eligibility total is claimed here.
