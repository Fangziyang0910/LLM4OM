建模方法/TriVAL

TriVAL

依次验证语义、数学模型与代码，必要时回溯修订。

本页内容

TriVAL 把建模检查分为语义、数学模型和代码三个阶段。每阶段都有构建、验证和修订，代码问题还可以回溯到数学模型阶段。

执行流程#

语义事实与验证 → 数学模型构建与验证 → 代码生成、执行与验证
                       ↑                  ↓
                       └── 必要时回溯修订 ─┘

它把不同层次的问题拆开：先检查问题如何被理解，再检查数学表达，最后检查代码实现与执行。过程页显示各阶段的中间产物和反馈。

怎样使用#

在运行设置选择 TriVAL，配合支持所需问题的建模库和后端。它适合需要逐阶段观察建模判断的场景，而不只是希望得到最终数值。

使用 DeepSeek 时，结构化输出需要强制工具选择，因此应在运行预设中关闭思考模式，配置见大模型预设。

查看哪些结果#

阅读语义事实、数学模型、代码及每阶段验证反馈。达到验证上限不代表验证通过；平台明确报告仍未通过的阶段，同时保留实际产物与求解结果。求解器的最优状态不能覆盖方法验证失败。

来源与平台适配#

核心图、节点、提示和循环来自 SCUT-EIPI/TriVAL 的固定提交。平台提供大模型和沙箱，将代码目标适配为 build_model(data) 返回原生模型。完整适配记录见文章末尾的原始文档入口。

当前参数#

参数来自部署时的方法预设，随每次运行记录保存。页面、命令行和 Python 接口均不提供单次运行的参数修改。

参数取值
max_validations5
max_code_executions20
