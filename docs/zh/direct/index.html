建模方法/Direct

Direct

一次生成数学模型与求解代码，再交给求解器计算。

本页内容
执行流程怎样使用查看结果实现来源当前参数

Direct 用一次大模型调用生成数学模型和完整求解代码，然后由平台执行代码并求解。它是优化对话的默认方法。

执行流程#

问题与附件 → 生成数学模型与代码 → 格式检查 → 求解

生成提示要求明确变量域、索引、单位、目标方向、数据来源和约束。输出缺少数学模型或代码时，运行会报告失败，不把空代码交给求解器。

怎样使用#

在运行设置选择 Direct，或直接使用优化对话默认配置。选择能表达问题的建模库和后端，再提交问题。它的调用流程短，便于先检查问题是否能形成清楚的模型。

附件预览可能不包含所有行；生成代码应通过 build_model(data) 读取完整附件。大数据结构绑定场景也可以考虑 BIND。

查看结果#

核对变量域、目标系数、资源上限和实际数值。Direct 没有求解后的语义复核循环；需要这一步时使用Feedback Repair。有效的不可行或无界状态仍是求解结果，不等于代码没有执行。

实现来源#

Direct 由 LLM4OM 项目维护。它与 Feedback Repair 共用生成提示和生成节点，区别在于后者增加求解、复核与有上限的修正循环。

当前参数#

参数来自部署时的方法预设，随每次运行记录保存。页面、命令行和 Python 接口均不提供单次运行的参数修改。

Direct 没有方法专属的预设参数。
