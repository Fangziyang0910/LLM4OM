比较方法与模型

对同一问题运行不同方法或大模型，核对结果和用量。

本页内容
发起对比怎样阅读比较表控制实验条件

方法对比用于保持问题不变，比较不同建模方法或预设模型的实际输出。它与改变业务条件的场景对比用途不同。

发起对比#

在手动工作台打开“运行设置”，开启“对比”，选择多个方法或模型预设，一次最多 12 个运行。确认问题、附件、建模库和后端后启动。

每项独立执行，保留自己的数学模型、代码、步骤和求解结果。点击对比表中的一行，可以进入对应运行检查。

怎样阅读比较表#

信息它能帮助判断什么
求解状态与目标值是否完成求解，模型的目标结果是否一致
用时本次实际执行耗时，不包括排队
LLM 调用与 token方法在这次问题上的调用成本
模型、代码与过程数值差异来自哪些建模选择或错误

目标值相同不代表模型完全相同，也不证明都正确。目标值不同时，先检查变量域、目标方向、约束和数据绑定，再讨论方法差异。

控制实验条件#

比较方法时，尽量固定问题、附件、预设模型、建模库和后端；比较大模型时，固定方法与求解环境。保存运行配置和报告，记录实际预设参数，而不是只记录方法名。

单题结果用于理解具体行为。要评估整体建模能力，需要一组有来源、参考答案和一致判定标准的问题；平台的并排展示本身不提供通用准确率结论。
