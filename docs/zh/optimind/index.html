建模方法/OptiMind

OptiMind

结合公开类型提示与多轮求解反馈检查模型。

本页内容
执行流程怎样使用当前公开范围来源与平台适配当前参数

OptiMind 结合问题类型提示与多轮求解反馈。它先匹配公开提示库中的类型，再生成模型、执行，并让大模型决定继续修订还是结束。

执行流程#

类型分类 → 公开提示 → 生成 → 求解 → 反馈
                              ↑      ↓ 修订或无代码最终回答
                              └──────┘

即使求解成功，也会提供反馈。大模型可以返回修正版，或以不包含代码的最终回答结束，保留最后一个实际执行的模型与结果。

怎样使用#

在运行设置选择 OptiMind，并配置适合问题的建模库与后端。旅行商问题可以匹配公开专项提示；未匹配到类型时使用通用检查提示。不要把方法名理解为自动加载了一个专用模型。

当前公开范围#

随平台提供的专项提示只有 TravelingSalesman 一类，共六条错误/提示对。平台没有补造未公开类型，也没有默认加入多数投票。当前使用一条轨迹，生成次数受下面的预设限制。

没有有效执行结果且回复缺少代码时，会继续请求代码；达到上限后报告失败，不把未执行回复当成完成。代码之外的解释与实际数值应分别核对。

来源与平台适配#

基于 OptiGuide/OptiMind 固定提交，论文。平台增加受公开库限制的分类节点，把执行反馈适配为求解状态与变量。未下载 OptiMind-SFT 权重；你可以通过预设连接自己部署的模型服务。

当前参数#

参数来自部署时的方法预设，随每次运行记录保存。页面、命令行和 Python 接口均不提供单次运行的参数修改。

参数取值
max_turns5
temperature0.6
top_p0.95
